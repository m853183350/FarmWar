# 渲染排序系统（Z-Ordering）

本文档定义 FarmWar 中所有可视对象的渲染排序规则，解决地块、作物、单位、建筑等对象出现在相同或相邻坐标时的遮挡关系错误。

---

## 一、问题描述

### 1.1 现状

项目中存在以下可视对象类型：

| 对象 | 基类 | 场景示例 | 原点设置 | 纹理大小(视觉) | 特殊偏移 |
|------|------|---------|---------|--------------|---------|
| 地块 | `BaseTile` (Sprite2D) | `dirt_1.tscn` | `centered=false` | 64×64 px | 无 |
| 作物(小麦) | `Crop` (Sprite2D) | `wheat_tire_1.tscn` | `centered=false` | 64×128 px | `offset=(0,-8)` → 向上偏移 64px |
| 单位(农场工人) | `UnitBase` (CharacterBody2D) | `farm_worker.tscn` | `centered=false` | 64×64 px | 无 |
| 建筑(未来) | 待定 | — | 待定 | 可能 128×128 或更大 | 待定 |
| 掉落物(未来) | 待定 | — | 待定 | ≤64×64 px | 待定 |

### 1.2 核心问题

当多个对象在相同或相邻地块坐标时，渲染顺序（谁挡谁）可能错误。典型的错误场景：

- **场景 A**：成熟小麦（纹理向上延伸 64px 到上方地块）与上方地块的作物 → 小麦的麦穗错误遮挡了上方作物
- **场景 B**：单位走到作物上方（y 更小的格子）→ 单位本应在作物"身后"却渲染在作物前面
- **场景 C**：单位走到作物下方（y 更大的格子）→ 单位本应在作物"身前"却被作物遮挡
- **场景 D**：未来的 2×2 大型建筑 → 建筑底部应在单位前方，顶部应在单位后方

### 1.3 根本原因

Godot 默认按节点在场景树中的顺序渲染（后创建的渲染在上），没有根据对象的空间位置动态调整渲染顺序。

---

## 二、设计目标

1. **Y 轴排序**：2D 俯视视角下，y 坐标越大的对象（越靠近屏幕下方，即越靠近"镜头"）渲染在越上层
2. **同一格内分优先级**：同坐标时，地块 < 作物 < 建筑 < 单位，确保单位始终在作物和地块上方
3. **多格对象正确**：2×2 等大型对象的底部行决定其排序，与穿过该区域的单位正确遮挡
4. **运行时高效**：排序计算 O(1)，不依赖每帧全量排序
5. **与帧率解耦**：排序更新在 tick 中完成，`_process` 只做画面插值

---

## 三、核心概念

### 3.1 排序锚点（Sorting Anchor）

每个可视对象有一个**排序锚点**，定义为该对象视觉上的"底部中心"。2D 俯视视角下，排序锚点的 y 值越大，对象越靠近镜头，渲染层级越高。

```
        镜头俯视方向
        ↓↓↓
        
   y=0  ┌────────────────────┐  ← 远处（渲染在底层）
        │  对象 A            │
   y=64 │  (排序锚点 y=64)    │
        ├────────────────────┤
        │  对象 B            │
  y=128 │  (排序锚点 y=128)   │  ← 近处（渲染在上层）
        └────────────────────┘
```

由于所有对象的 `centered = false`（原点在左上角），排序锚点计算公式为：

```
排序锚点 y = global_position.y + visual_height
```

其中 `visual_height` 是对象纹理在屏幕上的实际高度（像素），详见 [4.2](#42-视觉高度计算)。

### 3.2 渲染层（Render Layer）

同一排序锚点 y 值可能有多个对象（如地块和其上的作物），此时需要**层优先级**区分先后。

| 优先级 | 层名 | 包含对象 | 说明 |
|--------|------|---------|------|
| 0 | `GROUND` | 地块（Tile） | 最底层，地面本身 |
| 1 | `DECORATION` | 装饰物 | 纯粹的美术点缀 |
| 2 | `ITEM` | 掉落物 | 地面上的可拾取物品 |
| 3 | `RESOURCE` | 资源节点 | 矿石、树木等天然资源 |
| 4 | `CROP_LOW` | 作物（矮阶段） | 幼苗、发芽阶段，视觉不超出本格 |
| 5 | `CROP_TALL` | 作物（高阶段） | 成熟阶段，视觉可能超出本格 |
| 6 | `BUILDING` | 建筑 | 墙体、生产建筑等 |
| 7 | `UNIT` | 作战单位 | 所有可移动角色 |
| 8 | `EFFECT` | 特效 | 粒子、天气效果等（预留） |
| 9 | `OVERLAY` | UI 标记 | 选中高亮、血条等（预留，建议用 CanvasLayer） |

> **注意**：UI 类覆盖物（选中指示器、血条）建议放在独立的 `CanvasLayer` 上，不参与世界层排序。本节仅针对世界空间内的游戏对象。

## 四、Z-Index 计算公式

### 4.1 公式

```
z_index = floor(sorting_y / TILE_SIZE) × LAYER_MULTIPLIER + layer_priority
```

其中：
- `sorting_y` = 对象的排序锚点 y 值（世界坐标）
- `TILE_SIZE` = 64（地块像素大小）
- `LAYER_MULTIPLIER` = 10（常量，每个地块行内 10 个层级）
- `layer_priority` = 渲染层优先级（0~9）

> **注意**：使用地块行而非像素粒度是为了保持在 Godot 的 z_index 有效范围 [-4096, 4096] 内。对于最大 400×400 的地图，z_index 最大约 4000。

### 4.2 视觉高度计算

对于 Godot 的 Sprite2D（`centered = false`）：

```
visual_height = offset.y × scale.y + display_height × scale.y

其中:
  display_height = region_enabled ? region_rect.size.y : texture.get_height()
```

**推导**：`centered = false` 时，精灵的左上角位于 `position + offset × scale`，底部位于 `position + offset × scale + display_size × scale`，故底部 y = `position.y + offset.y × scale.y + display_height × scale.y`。

**各对象实例**：

| 对象 | offset.y | scale.y | display_height | visual_height |
|------|----------|---------|----------------|---------------|
| 地块 (dirt_1) | 0 | 8 | 8 | 64 |
| 小麦 (wheat_tire_1) | -8 | 8 | 16 | (-8)×8 + 16×8 = **64** |
| 农场工人 | 0 | 4 | 16 | 0 + 16×4 = **64** |
| 2×2 建筑(假设) | 0 | 8 | 16 | 0 + 16×8 = **128** |

> **关键发现**：虽然小麦的 offset 向上偏移了 64px，但纹理总高 128px，底部仍然对齐在 position.y + 64 处，与地块和单位一致。这是设计上的对齐——所有 1×1 物体的视觉底部都在 `grid_y × TILE_SIZE + TILE_SIZE`。

### 4.3 排序锚点的泛化计算

对于非 Sprite2D 对象（如包含多个子精灵的建筑），提供一个虚拟方法：

```gdscript
func get_sorting_y() -> float:
    return global_position.y + get_visual_height()
```

Sprite2D 子类的默认实现：

```gdscript
func get_visual_height() -> float:
    if not texture:
        return TILE_SIZE  # 64
    var disp_h := region_rect.size.y if region_enabled else texture.get_height()
    return offset.y * scale.y + disp_h * scale.y
```

非 Sprite2D 对象需要覆写 `get_visual_height()` 返回自定义值。

## 五、具体场景验证

### 5.1 同坐标：地块 + 作物 + 单位

假设地块 (3, 5)，上面有成熟小麦，一个工人站在旁边：

```
地块 (3,5):  sorting_y = 5*64 + 64 = 384, z = 384×10 + 0 = 3840
小麦 (3,5):  sorting_y = 5*64 + 64 = 384, z = 384×10 + 5 = 3845
工人 (3,5):  sorting_y = 5*64 + 64 = 384, z = 384×10 + 7 = 3847
```

渲染顺序：地块(3840) → 小麦(3845) → 工人(3847)。**正确** ✓

### 5.2 跨行遮挡：单位经过作物上方/下方

```
小麦在 (3,5): z = 3845
工人在 (3,4): sorting_y = 4*64+64 = 320, z = 3207
工人在 (3,6): sorting_y = 6*64+64 = 448, z = 4487
```

- 工人在作物**上方**（y=4）：3207 < 3845 → 工人**在后** ✓
- 工人在作物**下方**（y=6）：4487 > 3845 → 工人**在前** ✓

### 5.3 2×2 大型建筑

建筑锚点格 (3,5)，占地面积 (3,5)(4,5)(3,6)(4,6)，视觉高度 128px：

```
建筑: sorting_y = 5*64 + 128 = 448, z = 4480 + 6 = 4486
单位在 (3,4): sorting_y = 320, z = 3207  → 3207 < 4486 → 在后 ✓
单位在 (3,5): sorting_y = 384, z = 3847  → 3847 < 4486 → 在后 ✓ (单位被建筑遮挡，正常)
单位在 (3,6): sorting_y = 448, z = 4487  → 4487 > 4486 → 在前 ✓ (建筑底部一排)
单位在 (3,7): sorting_y = 512, z = 5127  → 5127 > 4486 → 在前 ✓
```

> 注意：建筑锚点格为最左上格。建筑占用的 4 格中，单位无法进入（`passable=false`），但在相邻格时遮挡关系正确。

### 5.4 高秆作物遮挡相邻上方地块

成熟小麦在 (0,5)，纹理顶部达到 y = 5×64 - 64 = 256（向上延伸 64px）。上方地块 (0,4) 的矮作物在 y = 320~384：

```
小麦 (0,5): sorting_y = 5*64+64 = 384, z = 3845
矮作物 (0,4): sorting_y = 4*64+64 = 320, z = 3204
```

矮作物 z=3204 < 小麦 z=3845。矮作物在下方（远离镜头），被上方的小麦麦穗遮挡。这是**正确的视觉效果**——小麦在地块 (0,4) 的"后面"（从镜头角度看，小麦在更远处）。

> **直觉验证**：想象相机在屏幕下方朝上拍摄。站在相机角度看，地块 (0,5) 比 (0,4) 更近。所以 (0,5) 上的小麦应该遮挡 (0,4) 上的物体。

## 六、实现方案

### 6.1 整体架构

```
                      ┌──────────────────────┐
                      │   ZIndexConfig        │
                      │   (class, 非 Autoload) │
                      │                      │
                      │  + LAYER_MULTIPLIER   │
                      │  + RenderLayer enum   │
                      │  + calc_z_index()     │
                      │  + get_sprite_height()│
                      └──────────────────────┘
                               │ 静态调用
          ┌────────────────────┼────────────────────┐
          │                    │                    │
   ┌──────▼──────┐    ┌───────▼───────┐    ┌───────▼──────┐
   │  BaseTile   │    │     Crop      │    │   UnitBase   │
   │  (Sprite2D) │    │   (Sprite2D)  │    │ (CharBody2D) │
   │             │    │               │    │              │
   │ update_z()  │    │ update_z()    │    │ update_z()   │
   └─────────────┘    └───────────────┘    └──────────────┘
```

### 6.2 ZIndexConfig 工具类

创建 `scripts/utils/z_index_config.gd`：

```gdscript
## 渲染排序配置与工具函数。
##
## 提供 z_index 计算公式、渲染层枚举、精灵视觉高度计算等。
## 所有需要参与排序的对象调用 [method calc_z_index] 设置自身 z_index。
class_name ZIndexConfig
extends RefCounted

# ============================================================
# 枚举 — 渲染层优先级
# ============================================================

enum RenderLayer {
    GROUND = 0,        ## 地块
    DECORATION = 1,    ## 装饰物
    ITEM = 2,          ## 掉落物
    RESOURCE = 3,      ## 资源节点
    CROP_LOW = 4,      ## 作物（矮阶段，视觉不超出本格）
    CROP_TALL = 5,     ## 作物（高阶段，视觉可能超出本格）
    BUILDING = 6,      ## 建筑
    UNIT = 7,          ## 作战单位
    EFFECT = 8,        ## 特效
    OVERLAY = 9,       ## UI 标记（建议独立 CanvasLayer）
}

# ============================================================
# 常量
# ============================================================

## 每像素 Y 可容纳的层级数。10 层足够覆盖所有 RenderLayer。
const LAYER_MULTIPLIER: int = 10

## 地块像素大小（需与 TerrainGenerator.tile_size 一致）。
const TILE_SIZE: int = 64

# ============================================================
# 静态方法
# ============================================================

## 根据排序锚点 y 值和渲染层计算 z_index。
##
## [param sorting_y] 对象视觉底部的世界 y 坐标
## [param layer]     渲染层优先级，取 [enum RenderLayer]
static func calc_z_index(sorting_y: float, layer: int) -> int:
    return floori(sorting_y) * LAYER_MULTIPLIER + clampi(layer, 0, 9)

## 获取 Sprite2D 的视觉高度（世界像素）。
##
## 适用于 [code]centered = false[/code] 的精灵。
## [code]visual_height = offset.y * scale.y + display_height * scale.y[/code]
static func get_sprite_visual_height(sprite: Sprite2D) -> float:
    var disp_h: float = 0.0
    if sprite.region_enabled:
        disp_h = sprite.region_rect.size.y
    elif sprite.texture:
        disp_h = sprite.texture.get_height()
    return sprite.offset.y * sprite.scale.y + disp_h * sprite.scale.y

## 获取 Sprite2D 的排序锚点 y（其 global_position.y + 视觉高度）。
static func get_sprite_sorting_y(sprite: Sprite2D) -> float:
    return sprite.global_position.y + get_sprite_visual_height(sprite)
```

### 6.3 各基类的修改

#### BaseTile

```gdscript
# 在 _ready() 末尾添加：
update_z_index()

# 新增方法：
func get_render_layer() -> int:
    return ZIndexConfig.RenderLayer.GROUND

func get_visual_height() -> float:
    return ZIndexConfig.get_sprite_visual_height(self)

func get_sorting_y() -> float:
    return global_position.y + get_visual_height()

func update_z_index() -> void:
    z_index = ZIndexConfig.calc_z_index(get_sorting_y(), get_render_layer())
```

#### Crop

```gdscript
# 在 plant() 方法末尾添加：
update_z_index()

# 新增方法：
func get_render_layer() -> int:
    # 根据生长阶段返回 CROP_LOW 或 CROP_TALL
    # 子类可以覆写此方法
    var stage_info: Dictionary = _stage_data[growth_stage] if growth_stage < _stage_data.size() else {}
    var frame_x: int = stage_info.get("frame_x", 0)
    # 简单的启发式：帧 0 是种子/幼苗 → CROP_LOW，否则 CROP_TALL
    # 更精确的判断可以在阶段数据的 passable 或自定义字段中标记
    return ZIndexConfig.RenderLayer.CROP_LOW if growth_stage <= 1 else ZIndexConfig.RenderLayer.CROP_TALL

func get_visual_height() -> float:
    return ZIndexConfig.get_sprite_visual_height(self)

func get_sorting_y() -> float:
    return global_position.y + get_visual_height()

func update_z_index() -> void:
    z_index = ZIndexConfig.calc_z_index(get_sorting_y(), get_render_layer())

# 在 _advance_stage() 中，emit 信号后添加：
update_z_index()  # 阶段变化可能改变渲染层
```

#### UnitBase

```gdscript
# 每 tick 移动后更新 z_index（在 _on_tick 中或 global_position 变化时）

func get_render_layer() -> int:
    return ZIndexConfig.RenderLayer.UNIT

func get_visual_height() -> float:
    # UnitBase 不是 Sprite2D，手动计算或使用 sprite 子节点
    if sprite and sprite.texture:
        return ZIndexConfig.get_sprite_visual_height(sprite)
    return TILE_SIZE

func get_sorting_y() -> float:
    return global_position.y + get_visual_height()

func update_z_index() -> void:
    z_index = ZIndexConfig.calc_z_index(get_sorting_y(), get_render_layer())

# 在 _execute_move_phase 末尾（grid_position 更新后）调用：
update_z_index()
```

### 6.4 调用时机总结

| 对象 | 何时更新 z_index |
|------|-----------------|
| 地块 | `_ready()` 时计算一次（地块不移动） |
| 作物 | `plant()` 时、生长阶段变化时 |
| 单位 | 每 tick 移动后（`_execute_move_phase` 末尾） |
| 建筑 | 放置时计算一次（建筑不移动） |
| 掉落物 | 生成时计算一次 |

### 6.5 与现有 z_index 的兼容

现有代码中已使用 z_index 的地方：

| 位置 | 当前值 | 处理方式 |
|------|--------|---------|
| `world.tscn` TileSelector | `z_index = 10` | 不变（TileSelector 是临时 UI，使用 CanvasLayer 更好） |
| `unit_base.tscn` SelectionIndicator | `z_index = 5` | 改为 `z_as_relative = false` 并设绝对高值，或移到 CanvasLayer |

> 建议：将 SelectionIndicator 和 HealthBar 等 UI 标记放到独立的 CanvasLayer，不参与世界排序。

## 七、多格对象处理

### 7.1 原则

- 多格对象的**逻辑位置**（`position` / `global_position`）放在其**最左上角**的锚点格
- 视觉高度按实际纹理计算（2×2 = 128px，3×3 = 192px）
- 排序锚点 = `position.y + visual_height`，即多格对象的**最底部行**

### 7.2 示例

一个 2×2 建筑，纹理为 128×128（16×16 像素纹理，8× 缩放），锚点格 (gx, gy)：

```
position = (gx * 64, gy * 64)
visual_height = 128
sorting_y = (gy * 64) + 128 = (gy + 2) * 64
z_index = (gy + 2) * 64 * 10 + BUILDING(6) = (gy + 2) * 640 + 6
```

排序效果：建筑以它底部那一行的 y 值参与排序，与同行的 1×1 对象相比，建筑排在单位之前、作物之后。

### 7.3 对寻路和碰撞的影响（不影响排序）

不可进入的多格对象会将其覆盖的所有地块的 `passable` 设为 `false`（已有设计），单位无法走入。排序系统无需对此做特殊处理。

可进入的多格对象等同于地面的处理方式。

## 八、性能分析

### 8.1 计算复杂度

- 每个对象更新 z_index：O(1)（一次乘法 + 一次加法）
- 无需全局排序，Godot 引擎根据 z_index 自动决定渲染顺序
- 总开销 ≈ (移动对象数) × O(1) per tick

### 8.2 预计负载

| 场景规模 | 地块数 | 移动单位 | 每 tick 更新次数 | 开销估算 |
|---------|--------|---------|-----------------|---------|
| 小型 (50×50) | 2500 | ~10 | 10 | 可忽略 |
| 中型 (100×100) | 10000 | ~50 | 50 | 可忽略 |
| 大型 (200×200) | 40000 | ~200 | 200 | < 0.1ms |

> 地块的 z_index 在创建时计算一次，不参与每 tick 更新。

### 8.3 优化方向（仅当出现瓶颈时考虑）

- 仅在地块视口范围内更新 z_index（viewport culling）
- 对静止单位跳过更新
- 使用 `z_index` 的 `z_as_relative` 特性减少子节点重排序

## 十、扩展预留

- **飞行单位**：需要自己的 RenderLayer（如 `FLYING = 8`，当前 EFFECT 可调整为 9），排序锚点可能使用 position.y 而非视觉底部
- **桥/隧道**：需要特殊的排序方式（部分在前、部分在后），此方案暂不覆盖
- **半透明混合**：当单位被建筑遮挡时，可以考虑对被遮挡的单位应用半透明 shader，而非简单的渲染顺序
- **粒子特效**：通常放在 EFFECT 层，使用绝对高 z_index 以确保在所有对象前方

## 十一、FAQ

**Q: 为什么不直接用 Godot 的 `y_sort_enabled`？**

A: Godot 的 `y_sort_enabled` 按子节点的 `position.y` 排序，但我们的对象原点都在左上角（`centered=false`），position.y 不能代表排序位置。虽然可以调整 `y_sort_origin`，但 `y_sort_enabled` 在同 Y 值时按场景树顺序排序，无法保证"地块 → 作物 → 单位"的类型优先级。使用 z_index 公式可以同时控制 Y 排序和类型优先级。

**Q: z_index 会不会溢出？**

A: Godot 的 `z_index` 是 `int`（32-bit signed），范围约 ±21 亿。对于 1000×1000 的地图（sorting_y 最大约 64000），z_index 最大约 640000，远低于溢出阈值。

**Q: 作物从 CROP_LOW 变为 CROP_TALL 时，z_index 变化会不会有闪烁？**

A: z_index 变化仅修改一个整数，在同帧内生效，不会有视觉闪烁。生长阶段变化发生在 tick 边界，与渲染帧独立。

**Q: 多个单位在同一格时，它们的遮挡关系如何？**

A: 同一格内，所有单位同属 UNIT 层（priority=7），z_index 完全相同。此时渲染顺序由 Godot 的场景树顺序决定（后添加的在上）。如需更精细的控制（如 HP 低的在上），可以在同层内使用亚像素 y 值或额外偏移。
