# 地块操作玩法架构设计

本文档描述玩家实际操作地块的核心玩法架构。涵盖三种操作模式（光标、采集、种植）的完整交互流程、新增/修改的组件、数据结构和事件流。

---

## 1. 概述

### 1.1 当前状态

项目已实现基础 UI 框架和调试用功能：

- **ModeSelector**：顶部模式选择器，支持 `cursor`（光标）和 `gather`（采集）默认模式，以及通过 `add_mode_for_family()` 动态添加的作物科模式（如 `poaceae`）
- **TileSelector**：处理鼠标拖拽框选，完成后弹出 TileContextMenu
- **TileContextMenu**：显示操作菜单（翻耕/挖掘/种植/收获 + 派遣版本），`show_debug_menu=true` 时收入 Debug 二级菜单
- **TileActions**：提供 `plow_tiles`、`dig_tiles`、`plant_crop`、`harvest_crop` 四个即时操作
- **UnitManager / FarmWorker**：通过 TaskData 驱动的工人派遣系统

但当前 TileSelector **不响应模式切换**——无论在何种模式，拖拽选地后都弹出相同菜单。且 Debug 菜单暴露了所有内部操作（派遣翻耕等），不是真实玩法。

### 1.2 目标行为

| 模式 | ModeSelector 中的 ID | 操作行为 |
|------|---------------------|---------|
| **光标模式** | `cursor` | 框选地块 → 弹出地块菜单（与现有一致） |
| **采集模式** | `gather` | 框选地块 → 根据地块类型/内容物自动确定采集动作，派遣工人执行 |
| **作物科模式** | 如 `poaceae` | 框选地块 → 弹出该科作物清单 → 选中作物 → 标记适合耕作的地块 → 工人自动循环：翻耕(如需)→种植→收获 |

**右键取消**：在任意模式的拖拽选择期间，按下鼠标右键取消本次选择。

```

                         │    ModeSelector      │
                         │  (顶部模式选择器)      │
                         └──────┬──────────────┘

                                ▼
                         ┌─────────────────────┐
                         │    TileSelector      │
                         │  (输入网关)           │
                         │                      │
                         │  LEFT → 开始框选     │

                            │       │       │
                   cursor   │ gather│       │ plant_family
                            ▼       ▼       ▼
              ┌────────┐ ┌────────┐ ┌──────────────┐
              │TileCtx │ │Gather  │ │  CropPicker  │
              │ Menu   │ │Actions │ │  (作物选择)    │
              └────────┘ └───┬────┘ └──────┬───────┘
                             │             │
                             │             ▼
                             │    ┌──────────────────┐
                             │    │ FarmlandManager  │
                             │    │ (农田分配+自动循环)│
                             │    └────────┬─────────┘
                             │             │
                             ▼             ▼
                      ┌─────────────────────────┐
                      │     UnitManager          │
                      │  (工人任务分发)            │
                      └────────────┬────────────┘
                                   │
                                   ▼
                      ┌─────────────────────────┐
                      │     FarmWorker × N      │
                      │  (执行 PLOW/PLANT/       │
                      │   HARVEST/DIG/GATHER)   │
                      └─────────────────────────┘
```

### 设计原则

1. **TileSelector 是输入网关**：统一处理鼠标输入，根据当前模式分发到不同处理路径
2. **事件驱动解耦**：所有跨系统通信通过 EventBus
3. **配置驱动**：采集动作映射、作物清单均从 JSON 配置加载
4. **渐进增强**：不破坏现有 `show_debug_menu` 调试路径，新模式与 Debug 菜单共存

```gdscript
func _unhandled_input(event: InputEvent) -> void:
    if _active_menu != null:
        return

    if event is InputEventMouseButton:
        # 右键取消拖拽
        if event.button_index == MOUSE_BUTTON_RIGHT and event.pressed:
            if _dragging:
                _cancel_drag()
                return

        if event.button_index == MOUSE_BUTTON_LEFT:
            if event.pressed:
                _on_mouse_pressed(event.position)
            else:
                _on_mouse_released(event.position)
    elif event is InputEventMouseMotion and _dragging:
        _drag_end = get_global_mouse_position()
        _preview_dirty = true
        queue_redraw()

func _cancel_drag() -> void:
    _dragging = false
    _preview_tiles.clear()
    _preview_dirty = false
    queue_redraw()
```

func _advance_stage() -> void:
    var old_stage: int = growth_stage
    growth_stage = mini(growth_stage + 1, _stage_data.size() - 1)
    _apply_stage_visuals()
    stage_changed.emit(old_stage, growth_stage)
    update_z_index()

## 4. 新增组件

### 4.1 GatherActions（`scripts/autoload/gather_actions.gd`）— Autoload

**职责**：根据地块类型和内容物判定适用的采集动作，生成 TaskData。

#### 配置来源（复用 `config/terrain_config.json`）

不新增独立配置文件。在现有 `terrain_config.json` 中为每种地形类型增加可选的 `gather_actions` 键。GatherActions 加载 terrain_config 后，根据地块所属地形类型查找对应采集动作，再按条件匹配。

```json
{
    "dirt": {
        "scene": "res://scenes/world/dirt_1.tscn",
        "weight": 0.60,
        "gather_actions": [
            {
                "id": "chop_tree",
                "name": "砍伐树木",
                "gather_action": "chop",
                "task_type": "GATHER",
                "conditions": [
                    { "type": "has_occupant", "value": "Tree" }
                ]
            }
        ]
    },
    "stone": {
        "scene": "res://scenes/world/stone_1.tscn",
        "weight": 0.25,
        "gather_actions": [
            {
                "id": "dig_stone",
                "name": "挖掘石材",
                "gather_action": "dig",
                "task_type": "DIG",
                "conditions": []
            }
        ]
    },
    "ocean": {
        "scene": "res://scenes/world/ocean_1.tscn",
        "weight": 0.15,
        "gather_actions": [
            {
                "id": "fish_ocean",
                "name": "钓鱼",
                "gather_action": "fish",
                "task_type": "GATHER",
                "conditions": [
                    { "type": "property", "key": "fishable", "value": true }
                ]
            }
        ]
    }
}
```

#### 核心方法

```gdscript
class_name GatherActions extends Node

## 匹配规则缓存。
var _rules: Array[Dictionary] = []

func _ready() -> void:
    _load_config()

## 判定所选地块的采集动作，生成 TaskData 数组。
## 无法匹配任何规则的地块被跳过。
func determine_and_create_tasks(tiles: Array[Vector2i]) -> Array[TaskData]:
    var tasks: Array[TaskData] = []
    var world: Node2D = _resolve_world()
    for grid_pos in tiles:
        var tile: Node2D = _find_tile(world, grid_pos)
        if tile == null:
            continue
        var rule: Dictionary = _match_rule(tile)
        if rule.is_empty():
            continue
        var task_type: int = _parse_task_type(rule.get("task_type", "GATHER"))
        var params: Dictionary = {
            "gather_action": rule.get("gather_action", ""),
            "rule_id": rule.get("id", ""),
        }
        tasks.append(TaskData.create(task_type, grid_pos, params))
    return tasks

## 遍历规则列表，返回第一个匹配的规则（优先级=数组顺序）。
func _match_rule(tile: Node2D) -> Dictionary:
    for rule: Dictionary in _rules:
        if _check_conditions(tile, rule.get("conditions", [])):
            return rule
    return {}
```

#### 配置加载

GatherActions 在 `_ready()` 时加载 `config/terrain_config.json`，提取各地形类型的 `gather_actions` 构建匹配规则。规则按地形类型分组——判定时先通过 tile 的 scene_file_path 反向匹配到地形类型，再遍历该类型下的 gather_actions 按条件筛选。

**为何不新增独立配置文件**：采集动作与地形类型强关联（石地→挖掘、水域→钓鱼），放在 terrain_config 中可一并查看/维护。且 TerrainGenerator 已加载该配置，GatherActions 复用同一文件避免数据重复。

**为何是 Autoload**：采集判定逻辑需访问 world 节点和 tile 数据，类似 TileActions。作为 Autoload 可被 TileSelector、AI 等任意系统调用。

#### 核心 API

```gdscript
class_name CropPicker extends CanvasLayer

const CROPS_CONFIG_DIR: String = "res://config/crops/"

## 全量作物数据缓存（_ready 时一次性加载）。
## 结构：[{crop_id, crop_name, plant_family, tier, description, scene_path, unlocked, ...}, ...]
var _all_crops: Array[Dictionary] = []


func _ready() -> void:
    _load_all_crops()

## 在节点就绪时一次性扫描 config/crops/ 目录，加载全部作物数据。
## 避免每次弹出选择器时重复读写磁盘。
func _load_all_crops() -> void:
    var dir: DirAccess = DirAccess.open(CROPS_CONFIG_DIR)
    if dir == null:
        return
    dir.list_dir_begin()
    var file_name: String = dir.get_next()
    while not file_name.is_empty():
        if file_name.ends_with(".json") and not dir.current_is_dir():
            var data: Dictionary = _load_crop_json(CROPS_CONFIG_DIR + file_name)
            if not data.is_empty():
                # 默认已解锁（后续可通过 set_crop_unlocked 控制）
                if not data.has("unlocked"):
                    data["unlocked"] = true
                _all_crops.append(data)
        file_name = dir.get_next()
    dir.list_dir_end()

## 显示指定植物科的作物选择器。
## 从 [member _all_crops] 中筛选已解锁且匹配 plant_family 的作物。
func show_for_family(family_id: String) -> void:
    var crops: Array[Dictionary] = _filter_by_family(family_id)
    if crops.is_empty():
        print("CropPicker: 植物科 '%s' 下无可用作物" % family_id)
        picker_cancelled.emit()
        queue_free()
        return
    _populate_list(crops)
    _adjust_position()
    visible = true

## 从全量缓存中筛选指定科且已解锁的作物。
func _filter_by_family(family_id: String) -> Array[Dictionary]:
    var results: Array[Dictionary] = []
    for data: Dictionary in _all_crops:
        if data.get("plant_family", "").to_lower() == family_id.to_lower():
            if data.get("unlocked", false):
                results.append(data)
    return results

## 设置指定作物的解锁状态。
## 供科技树等外部系统调用，控制玩家可选作物范围。
func set_crop_unlocked(crop_id: String, unlocked: bool) -> void:
    for data: Dictionary in _all_crops:
        if data.get("crop_id", "") == crop_id:
            data["unlocked"] = unlocked
            return
```

#### 数据来源与解锁控制

在 `_ready()` 时一次性扫描 `config/crops/` 目录下所有 JSON 文件，缓存到 `_all_crops`。后续 `show_for_family()` 仅做内存筛选，避免每次弹出选择器时重复读写磁盘。

每个作物 JSON 可新增 `unlocked` 字段（可选，默认 `true`）：

```json
{
    "crop_id": "wheat_tier1",
    "crop_name": "原始小麦",
    "plant_family": "poaceae",
    "tier": 1,
    "unlocked": true
}
```

当 `unlocked: false` 时，该作物不会出现在 CropPicker 列表中。科技树或任务系统通过 `set_crop_unlocked(crop_id, true)` 动态解锁。

### 4.3 FarmlandManager（`scripts/autoload/farmland_manager.gd`）— Autoload

**职责**：管理地块→作物分配关系，驱动工人的自动耕作循环。这是整个"自动循环"的核心。

#### 数据结构

```gdscript
## 地块分配表：{ Vector2i(3,5): {"crop_id": "wheat_tier1", "state": "growing"} }
var _assignments: Dictionary = {}

## 分配状态枚举。
enum AssignState {
    NEEDS_PLOW,    ## 需要先翻耕（地块是 DIRT）
    NEEDS_PLANT,   ## 可以种植（地块已是 FARMLAND 且无作物）
    GROWING,       ## 作物生长中
    NEEDS_HARVEST, ## 作物已成熟，等待收获
}
```

#### 核心流程

```
assign_tiles(tiles, crop_id)
    │
    ▼
遍历每个地块
    ├── DIRT (可翻耕) → state=NEEDS_PLOW → 创建 PLOW 任务
    ├── FARMLAND (空) → state=NEEDS_PLANT → 创建 PLANT 任务
    ├── FARMLAND (已有作物) → 不操作（或先收获再种植）
    └── 其他类型 → 跳过

存入 _assignments[tile] = {crop_id, state}

监听 EventBus：
    worker_task_completed(worker_id, task)
        ├── PLOW 完成 → state=NEEDS_PLANT → 创建 PLANT 任务
        ├── PLANT 完成 → state=GROWING（等待作物自然成熟）
        └── HARVEST 完成 → state=NEEDS_PLANT → 创建 PLANT 任务（循环！）

    crop_matured(crop_node, grid_pos, crop_id)  ← 核心驱动
        └── 对应的已分配地块 → state=NEEDS_HARVEST → 创建 HARVEST 任务

    crop_harvested(yields, crop_id) [作为兜底]
        └── 对应的已分配地块 → state=NEEDS_PLANT → 创建 PLANT 任务
```

#### 核心方法

```gdscript
class_name FarmlandManager extends Node

## 将一批地块分配给指定作物，启动自动耕作循环。
func assign_tiles(tiles: Array[Vector2i], crop_id: String) -> void:
    var valid_count: int = 0
    var world: Node2D = _resolve_world()
    for grid_pos in tiles:
        var tile: Node2D = _find_tile(world, grid_pos)
        if tile == null:
            continue

        var tile_type: int = _get_tile_type(tile)

        # DIRT → 先翻耕再种植
        if tile_type == 0:  # DIRT
            _assignments[grid_pos] = {"crop_id": crop_id, "state": AssignState.NEEDS_PLOW}
            _create_plow_task(grid_pos, crop_id)
            valid_count += 1

        # FARMLAND 且无作物 → 直接种植
        elif tile_type == 3 and not _has_crop(tile):  # FARMLAND
            _assignments[grid_pos] = {"crop_id": crop_id, "state": AssignState.NEEDS_PLANT}
            _create_plant_task(grid_pos, crop_id)
            valid_count += 1

        # FARMLAND 已有作物 → 先收获再重新种植
        elif tile_type == 3 and _has_crop(tile):
            if _is_crop_mature(tile):
                _assignments[grid_pos] = {"crop_id": crop_id, "state": AssignState.NEEDS_HARVEST}
                _create_harvest_task(grid_pos, crop_id)
                valid_count += 1
            # 未成熟则不操作（保留现有作物）

    print("FarmlandManager: %d/%d 个地块已分配给 %s" % [valid_count, tiles.size(), crop_id])
    if valid_count > 0 and EventBus:
        EventBus.farmland_assigned.emit(tiles, crop_id)

## 取消指定地块的自动耕作分配。
func unassign_tiles(tiles: Array[Vector2i]) -> void:
    for grid_pos in tiles:
        _assignments.erase(grid_pos)
    if EventBus:
        EventBus.farmland_unassigned.emit(tiles)

## 检查地块是否已分配给某种作物。
func get_assignment(grid_pos: Vector2i) -> Dictionary:
    return _assignments.get(grid_pos, {})

## 检查地块是否已分配给自动循环。
func is_assigned(grid_pos: Vector2i) -> bool:
    return _assignments.has(grid_pos)

## 获取所有分配了指定作物的地块坐标。
func get_tiles_for_crop(crop_id: String) -> Array[Vector2i]:
    var tiles: Array[Vector2i] = []
    for grid_pos in _assignments:
        var info: Dictionary = _assignments[grid_pos]
        if info.get("crop_id", "") == crop_id:
            tiles.append(grid_pos)
    return tiles
```

#### 事件驱动的循环推进

```gdscript
func _ready() -> void:
    EventBus.worker_task_completed.connect(_on_worker_task_completed)
    EventBus.crop_matured.connect(_on_crop_matured)
    # crop_harvested 作为兜底：当工人/手动收获已分配地块后自动补种
    EventBus.crop_harvested.connect(_on_crop_harvested)

func _on_worker_task_completed(worker_id: StringName, task: TaskData) -> void:
    var grid_pos: Vector2i = task.target_tile
    if not _assignments.has(grid_pos):
        return

    var info: Dictionary = _assignments[grid_pos]
    var crop_id: String = info.get("crop_id", "")
    var state: int = info.get("state", -1)

    match task.task_type:
        TaskData.TaskType.PLOW:
            if state == AssignState.NEEDS_PLOW:
                info["state"] = AssignState.NEEDS_PLANT
                _assignments[grid_pos] = info
                _create_plant_task(grid_pos, crop_id)

        TaskData.TaskType.PLANT:
            if state == AssignState.NEEDS_PLANT:
                info["state"] = AssignState.GROWING
                _assignments[grid_pos] = info
                # 不再在此处创建 HARVEST 任务 — 由 crop_matured 信号驱动

        TaskData.TaskType.HARVEST:
            if state == AssignState.NEEDS_HARVEST:
                info["state"] = AssignState.NEEDS_PLANT
                _assignments[grid_pos] = info
                _create_plant_task(grid_pos, crop_id)

## 作物成熟时自动创建 HARVEST 任务（核心循环推进点）。
## 作物在 _advance_stage() 进入最终阶段时通过 EventBus 发出。
func _on_crop_matured(crop_node: Node2D, grid_pos: Vector2i, crop_id: String) -> void:
    if not _assignments.has(grid_pos):
        return
    var info: Dictionary = _assignments[grid_pos]
    if info.get("state", -1) == AssignState.GROWING:
        info["state"] = AssignState.NEEDS_HARVEST
        _assignments[grid_pos] = info
        _create_harvest_task(grid_pos, crop_id)

## 兜底：当通过手动即时操作收获已分配地块时，自动补种。
func _on_crop_harvested(yields: Array, crop_id: String) -> void:
    for grid_pos in _assignments:
        var info: Dictionary = _assignments[grid_pos]
        if info.get("state", -1) == AssignState.GROWING and info.get("crop_id", "") == crop_id:
            var world: Node2D = _resolve_world()
            var tile: Node2D = _find_tile(world, grid_pos)
            if tile == null or not _has_crop(tile):
                info["state"] = AssignState.NEEDS_PLANT
                _assignments[grid_pos] = info
                _create_plant_task(grid_pos, info["crop_id"])
```

**关键设计决策**：

1. **状态机而非轮询**：通过监听 `worker_task_completed`、`crop_matured` 和 `crop_harvested` 事件推进状态，不依赖 tick 轮询。规避了"在每个 tick 遍历所有分配地块"的性能开销。

2. **通过 `crop_matured` 信号驱动 HARVEST**（核心改进）：PLANT 完成后状态进入 GROWING，不再立即或延迟创建 HARVEST 任务。而是等待作物自身在 `_advance_stage()` 进入最终阶段时发出 `EventBus.crop_matured` 信号，FarmlandManager 监听到后创建 HARVEST 任务。这完全消除了轮询/延迟推断/任务反复失败等 hack，实现精准的"成熟即收获"。

3. **`crop_harvested` 作为兜底**：当通过光标模式的手动即时操作（而非工人）收获已分配地块时，同样触发补种，确保自动循环不会因手动干预而中断。

## 5. 配置扩展

### 5.1 扩展 `config/terrain_config.json`

在现有 `terrain_config.json` 中为每种地形类型增加可选的 `gather_actions` 键，而非新增独立配置文件。结构见 4.1 节配置示例。

**条件匹配器**支持以下条件类型（每个 gather_action 条目内）：

| 条件类型 | 说明 | 示例 |
|---------|------|------|
| `has_occupant` | 地块上有指定 class_name 的内容物 | `"Tree"`, `"Crop"` |
| `property` | 匹配地块的元数据属性 | `{"key": "fishable", "value": true}` |

条件为 AND 逻辑，空条件数组表示匹配该地形类型下的所有地块（如石地无条件挖掘）。地块的场景路径匹配通过 terrain_config 的 `scene` 键自动完成，无需在条件中重复声明。

### 5.2 `config/crops/*.json` 无需修改

现有作物配置已包含 `plant_family` 字段，CropPicker 直接使用。后续新增作物时只需确保：
- JSON 包含 `plant_family`（如 `"poaceae"`）
- `mode_definitions.json` 的 `plant_icons` 中有对应科的图标映射

## 6. 数据流详解

### 6.1 采集模式完整流程

```
1. 玩家点击 ModeSelector 中的"采集"方框（或按 2）
2. ModeSelector._select_slot(1)
   → mode_selected.emit("gather")
   → EventBus.mode_changed.emit("gather")
3. TileSelector._on_mode_changed("gather")
   → mode = LeftClickMode.GATHER
4. 玩家左键拖拽框选地块
   → TileSelector._on_mouse_pressed → 开始框选
5. (可选) 玩家右键 → _cancel_drag() → 框选取消
6. 玩家松开左键
   → TileSelector._on_mouse_released
   → _handle_gather(selected_tiles)
7. GatherActions.determine_and_create_tasks(tiles)
   → 遍历每个地块，按规则匹配
   → 生成 TaskData 数组
8. UnitManager.distribute_tasks(tasks)
   → 分配给空闲工人
9. FarmWorker 依次执行：
   → 移动到目标地块
   → 执行工作动画（DIG/GATHER）
   → 通过 TileActions 完成地块操作
10. EventBus.worker_task_completed.emit(...)
```

### 6.2 种植模式完整流程

```
1. 玩家点击 ModeSelector 中的"禾本科"方框（或按 3）
2. ModeSelector → mode_changed.emit("poaceae")
3. TileSelector._on_mode_changed("poaceae")
   → mode = LeftClickMode.PLANT_FAMILY
   → _current_family_id = "poaceae"
4. 玩家左键拖拽框选地块
5. (可选) 右键取消
6. 松开左键 → _handle_plant_family(selected_tiles)
7. CropPicker.show_for_family("poaceae")
   → 从 _all_crops 内存缓存中筛选已解锁的植物科作物
   → 显示作物清单（如：原始小麦）
8. 玩家点击"原始小麦"按钮
   → CropPicker.crop_selected.emit("wheat_tier1")
9. TileSelector._on_crop_selected("wheat_tier1", tiles)
10. FarmlandManager.assign_tiles(tiles, "wheat_tier1")
    → 遍历每个地块：
      ├── DIRT → 创建 PLOW 任务 → state=NEEDS_PLOW
      ├── FARMLAND(空) → 创建 PLANT 任务 → state=NEEDS_PLANT
      └── 其他 → 跳过
    → EventBus.farmland_assigned.emit(tiles, "wheat_tier1")
11. UnitManager 分发任务 → 工人执行

12. [自动循环 — 通过 crop_matured 信号驱动]
    工人完成 PLOW → FarmlandManager 创建 PLANT → state=NEEDS_PLANT
    工人完成 PLANT → state=GROWING（不创建 HARVEST，等待作物自然成熟）
    Crop 生长到最终阶段 → _advance_stage() 发出 EventBus.crop_matured(grid_pos, crop_id)
    FarmlandManager 监听到 crop_matured → state=NEEDS_HARVEST → 创建 HARVEST 任务
    工人完成 HARVEST → state=NEEDS_PLANT → 创建 PLANT 任务
    → 无限循环直到玩家手动 unassign
```
