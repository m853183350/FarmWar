# 道具和 Buff 系统

本章节记录道具系统的核心职责、架构设计、道具定义格式和扩展方向。Buff 系统为后续规划，当前暂不实现。

> 更新：2026-06-25 — 新增 MODIFIER 效果系统（ModifierRegistry + Domain），jinkela 验证通过

## 目标

- 为玩家提供**被动道具**收集机制（类似 roguelike 游戏中的道具/遗物）
- 支持两种触发模型：
  - **INSTANT**（事件驱动）— 监听 EventBus 信号，触发时执行效果
  - **MODIFIER**（状态驱动）— 持有期间持续生效，游戏系统被动查询聚合值
- 采用**数据驱动**架构 — 道具定义存储在 JSON 配置文件中，绝大多数道具无需独立脚本
- 道具共性逻辑提取到 `PropManager` 和 `PropData` 中

## 范围

- **已实现**：
  - INSTANT 被动触发型道具（监听游戏事件 → 执行效果）
  - MODIFIER 被动修饰型道具（注册修饰器 → Domain 链聚合 → 系统查询）
- **后续扩展**：消耗品、装备、DURATION 限时 Buff/Debuff

## 核心概念

| 类/文件 | 类型 | 说明 |
|---------|------|------|
| `PropManager` | Node | 道具管理器，按 `prop_category` 路由到 EffectManager 或 ModifierRegistry |
| `EffectManager` | RefCounted | 效果管理器，处理 INSTANT 效果注册和执行 |
| `ModifierRegistry` | RefCounted | 修饰器注册中心，管理 MODIFIER 效果的领域计算链 |
| `Domain` | RefCounted | 领域类，维护单领域内有序修饰器链 + target_filter 过滤 |
| `PropData` | RefCounted | 道具定义数据类，含 `prop_category`、`modifier` 等字段 |
| `PropEffectBase` | RefCounted | 效果基类，所有 INSTANT/DURATION 效果继承它 |
| `config/items/props/*.json` | JSON | 道具定义配置文件，每个道具一个文件 |

## 架构

```
Player (Node)
├── Storage (Storage)                         # 仓库
└── PropManager (PropManager)                 # 道具管理器
    ├── props: Dictionary                     # {prop_id: count}
    ├── prop_library: Dictionary              # {prop_id: PropData}
    ├── _signal_bindings: Dictionary          # 信号→INSTANT 道具列表
    │
    ├── _effect_manager: EffectManager        # INSTANT 效果 (event-driven)
    │   ├── registry: {effect_type: PropEffectBase}
    │   └── execute(prop_data, count, trigger_context)
    │       └── 如: AddStorageItemEffect → storage.add_item("money", 1.0)
    │
    └── _modifier_registry: ModifierRegistry  # MODIFIER 效果 (state-driven, 新增)
        ├── _domains: {"tile": Domain, ...}
        │   └── Domain._chain: [{prop_id, stat, value, priority, tags, target_filter}, ...]
        ├── register_modifier(...)  /  unregister_modifier(...)
        └── calculate(domain, stat, base, context) → float
            └── 查询方: BaseTile._calculate_fertility()
                 → (base + mod1) × mult + mod2
```

## 道具属性

每个道具定义包含以下属性：

| 属性 | 类型 | 说明 |
|------|------|------|
| `prop_id` | String | 唯一标识符（snake_case） |
| `prop_name` | String | 显示名称（中文） |
| `description` | String | 风味描述文字 |
| `rarity` | String | 稀有度：COMMON / UNCOMMON / RARE / EPIC / LEGENDARY |
| `icon_path` | String | 图标纹理路径（暂可留空） |
| `max_stack` | int | 最大持有数量（0 = 无限制） |
| `prop_category` | String | **新增** — 道具类别：`"instant"`（默认）、`"modifier"`、`"duration"` |
| `trigger_signal` | String | INSTANT 道具的触发信号名 |
| `trigger_condition` | Dictionary | 触发条件（预留） |
| `effect_type` / `effects` | String / Array | INSTANT 道具的效果配置（兼容新旧两种格式） |
| `modifier` | Dictionary | **新增** — MODIFIER 道具的修饰器配置 |
| `priority` | int | **新增** — 全局排序优先级 |
| `requires` | Array[String] | **新增** — 前置道具 ID 列表（Phase 2 检查） |
| `conflicts_with` | Array[String] | **新增** — 互斥道具 ID 列表（Phase 2 检查） |
| `tags` | Array[String] | 分类标签 |

## 触发-效果机制

### MODIFIER 效果（新增 — Phase 0+1）

MODIFIER 道具不需要 `trigger_signal` 和 `effects`，改用 `modifier` 配置：

```json
{
    "prop_id": "jinkela",
    "prop_category": "modifier",
    "modifier": {
        "target_domains": ["tile"],
        "stat": "fertility_modifier_1",
        "value": 0.3,
        "priority": 100,
        "tags": ["flat"],
        "target_filter": { "tile_type": "farmland" }
    }
}
```

| modifier 字段 | 类型 | 说明 |
|---------------|------|------|
| `target_domains` | Array[String] | 影响哪些领域 |
| `stat` | String | 影响的具体属性名 |
| `value` | float | 每堆叠的修正值 |
| `priority` | int | 排序优先级（越小越先计算） |
| `tags` | Array[String] | 计算标签：`flat` / `additive` / `multiplicative` / `override` |
| `target_filter` | Dictionary | 生效范围过滤（如 `{"tile_type": "farmland"}`） |
| `calculator` | — | （可选）自定义计算 Callable |

MODIFIER 修饰器标签：

| 标签 | 计算方式 | 说明 |
|------|---------|------|
| `flat` | `result += value` | 固定值加成 |
| `additive` | `result += base_value × value` | 基于基础值的叠加 |
| `multiplicative` | `result *= 1.0 + value` | 乘算因子 |
| `override` | `result = max(result, value)` | 取最高值 |

### INSTANT 效果（原有）

| 触发标识 | EventBus 信号 | 触发时机 |
|----------|--------------|----------|
| `crop_matured` | `crop_matured` | 作物进入成熟阶段 |
| `crop_harvested` | `crop_harvested` | 作物被收获 |
| `crop_stage_changed` | `crop_stage_changed` | 作物生长阶段变化 |

INSTANT 效果类型：

| 效果标识 | 类别 | 说明 |
|----------|------|------|
| `add_storage_item` | INSTANT | 向 Storage 添加物品 |

### 两大系统组合（DURATION — Phase 4 规划）

INSTANT（事件驱动）和 MODIFIER（状态驱动）可通过 DURATION 类别组合：

```
EffectManager（事件触发 + 生命周期管理）
  on_apply  → ModifierRegistry.register_modifier()
  (持续 N 个 tick)
  on_remove → ModifierRegistry.unregister_modifier()
```

详见 [0624效果系统优化方案.md](../0624效果系统优化方案.md) 第十二章。

## 事件流（以 sunshine_coin 为例 — INSTANT）

```
Crop._advance_stage()
  → EventBus.crop_matured.emit(crop_node, grid_pos, crop_id)
    → PropManager._on_crop_matured(...)
      → _process_trigger(&"crop_matured", trigger_context)
        → _effect_manager.execute(prop_data, count, trigger_context)
          → AddStorageItemEffect.execute()
            → context["storage"].add_item("money", 1.0)
```

## 数据流（以 jinkela 为例 — MODIFIER）

```
PropManager.add_prop("jinkela")
  → _apply_modifier()
    → ModifierRegistry.register_modifier()
    → EventBus.tile_modifiers_changed.emit()

BaseTile.update_properties()
  → _calculate_fertility()
    → _build_modifier_context() → {"tile_type": "farmland"}
    → PropManager.query_modifier("tile", "fertility_modifier_1", 0.0, context)
      → ModifierRegistry.calculate(...)
        → Domain.calculate(...)
          → _matches_filter() → tile_type == "farmland" ✓
          → flat: result += 0.3 × count
    → fertility = (0.8 + 0.3×count) × 1.0 + 0.0
```
