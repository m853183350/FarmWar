# FarmWar

中文名（暂定）：农场战争

定位：以种田为资源获取核心，以收获的作物为基础，建造各种自动化设备、防御建筑和军队，抵御外部进攻，攻打外部敌人最终获得胜利的2D战略类游戏

# 游戏流程

游戏时长：正常游玩一局在20分钟至60分钟之间，简单模式可以缩短到10分钟

玩家操作：PC端键鼠操作，上帝视角俯视，2D界面

# 游戏特色

以现实生物学的“科”作为作物的分类方式，每个科的作物有独特的收益、科技树和兵种

游戏侧重点在于如何高效利用现有资源，提高作物水平，从而获得更强大的军队

风格：以植物为主，包括军队、建筑、都与植物息息相关

# 底层逻辑

以下系统贯穿整个游戏，是所有上层系统的运行基础。

## Tick 系统

游戏逻辑以 **tick** 为单位推进，与画面渲染分离（类似 Unity 的 `FixedUpdate` 或 Minecraft 的 tick 机制）。

- **默认间隔**：50ms（即每秒 20 tick）
- **可配置**：通过配置文件或设置界面修改 tick 间隔
- **适用范围**：所有与帧率无关的逻辑计算，包括但不限于：
  - 作物生长时间计算
  - 实体移动与寻路步进
  - 战斗伤害结算
  - Buff 持续时间倒数
  - 天气效果更新
  - 敌人 AI 决策
- **实现方式**：由 Autoload `TickSystem` 管理，每 tick 发出 `tick_elapsed(delta: float)` 信号，各系统监听该信号执行逻辑
- **与渲染的关系**：渲染帧率独立于 tick，通过插值保证视觉平滑

## 调试系统

提供运行时调试能力，通过键盘快捷键激活调试控制台。

- **激活方式**：按下 `/` 键弹出调试输入框
- **功能**：输入调试指令，实时修改游戏状态、查询信息、触发事件
- **指令示例**：
  - `give [item_id] [count]` — 给予物品
  - `set_time [value]` — 设置游戏时间/速度
  - `spawn [entity_type] [x] [y]` — 生成实体
  - `god` — 无敌模式
  - `reveal` — 全图视野
  - `kill_all` — 清除所有敌人
- **钩子机制**：各系统需预留可供外部调用的调试方法，通过 `DebugConsole` 统一注册和路由
- **实现方式**：由 Autoload `DebugConsole` 管理，维护指令注册表，解析输入并分发到对应系统的钩子方法
- **调试叠加层**：按下 `F3` 键同时在屏幕左侧和右侧显示实时调试数据叠加层（纯文本，不阻挡操作），由 `DebugUI` autoload 统一管理输入和显隐；内容由各系统通过 `DebugOverlay`（右侧）和 `DebugOverlayLeft`（左侧）autoload 写入；按 `F4`/`F5` 同步翻页。详见 [Docs/ui/debug_overlay.md](ui/debug_overlay.md)

## 材质与Shader管理系统

与画面渲染紧密配合，统一管理游戏中所有的 ShaderMaterial 和 gdshader 资源。

**核心职责：**

- **统一资源管理** — 所有 `.gdshader` 和 `.material` / `.tres` (ShaderMaterial) 放在 `resources/` 中，按系统分类
- **材质缓存与复用** — 同类型对象（同种作物、同种单位）共享同一个 ShaderMaterial 实例，通过 `shader_parameter` 区分状态
- **运行时动态效果** — 作物生长颜色渐变、枯萎灰度化、单位受伤闪烁、选中高亮、天气特效等均通过修改 `shader_parameter` 实现，避免频繁更换纹理
- **加载与预编译** — 游戏启动时预加载常用 shader，避免首次渲染时的编译卡顿

**实现方式：**

- 材质管理器作为 Autoload `MaterialManager` 或在 `scripts/autoload/` 中实现
- 提供 `get_material(id: StringName) -> ShaderMaterial` 接口
- 提供 `apply_effect(node: Node2D, effect: StringName, params: Dictionary)` 便捷方法
- 从 JSON 配置加载材质索引表（`config/material_index.json`），便于扩展新材质

**shader 类型：**
- 全部使用 `canvas_item`（2D 渲染），与项目 mobile 渲染器兼容
- 避免 `spatial` shader（3D）以保持性能

**目录结构：**
```
resources/
├── shaders/                   # .gdshader 着色器源码
│   ├── crops/                 #   作物着色器（生长、枯萎等）
│   │   └── crop_grow.gdshader
│   ├── units/                 #   单位着色器（高亮、闪烁等）
│   ├── environment/           #   环境着色器（天气、水面等）
│   └── common/                #   通用工具函数/模板
└── materials/                 # .material / .tres 材质资源
    ├── crops/                 #   作物材质
    ├── units/                 #   单位材质
    └── environment/           #   环境材质
```

**使用示例：**
```gdscript
# 给作物应用生长阶段的颜色
var mat: ShaderMaterial = MaterialManager.get_material("crop_grow")
crop_sprite.material = mat
mat.set_shader_parameter("growth_progress", 0.6)
mat.set_shader_parameter("health", 0.9)

# 收获时的金色闪烁（通过临时修改参数实现）
mat.set_shader_parameter("growth_progress", 1.0)
```

# 主要玩法

背景故事：玩家是一名星际游荡者，为了逃离过去前往未知的星球，落地后，玩家需要使用基础装备收集物资，开坑荒地、种植作物、赚钱、修复科技、进化作物、最终消灭所有敌人称霸星球（军事胜利），或者带着亿万财产离开（财富胜利）

玩家本人为俯视视角，可以控制友方单位执行操作。玩家所做的事是“发指令”，如圈定一块范围开垦农田，或是指派先锋探索未知区域。下达指令后，友方单位就会自动执行任务。

玩家在开局可以选择一个派系，不同派系有不同的开局种子和专长，其余的作物可通过游戏进程获取。

从中期开始，就会有敌人开始入侵，玩家需要建造出自己的植物大军抵御进攻

**玩家的操作特点** 会频繁操作地块，会频繁选中单位并给出指令，会频繁开关仓库、商店等覆盖型UI界面（此时会阻止玩家操作地块和指挥单位，或是点击其他无关UI）、会使用大量可配置的快捷键进行操作


# 数值期望

玩家一局游戏中能解锁的作物应当有限，所以需在考虑在多物种组合，和单物种飞升之间取舍
