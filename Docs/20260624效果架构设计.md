提问：以后的道具效果可能有数十种甚至上百种，能影响到的范围也是五花八门（玩家、仓库、商店、地形、科技、UI等等等等），应该如何设计

回答：

核心原则：效果定义和作用目标彻底解耦，按领域各自维护计算链。

整体架构
EffectDefinition（效果定义，纯数据）
  │
  ├── target_domains: ["tile", "player", "warehouse"]  ← 作用在哪
  ├── priority: int
  ├── condition: Callable  ← 触发条件
  └── calculator: Callable ← 怎么算
        │
        ▼ 按 domain 分发
        
┌──────────┬──────────┬──────────┬──────────┐
│ TileDomain│PlayerDomain│ShopDomain│WarehouseDomain│
│ModifierChain│ModifierChain│ModifierChain│ModifierChain│
└──────────┴──────────┴──────────┴──────────┘
核心代码
1. 效果定义（纯数据，不继承任何东西）
gdscript
# effect_def.gd
class_name EffectDefinition
extends RefCounted

var id: String
var name: String
var target_domains: Array[String]    # ["tile", "player", "shop"...]
var priority: int = 0
var condition: Callable              # func(): bool，满足才生效
var calculator: Callable             # func(current_value) -> new_value

# 跨效果依赖/互斥
var requires: Array[String] = []    # 需要这些效果先存在
var conflicts_with: Array[String] = []  # 和这些效果互斥
2. 领域管理器（每个领域一个）
gdscript
# domain.gd
class_name Domain
extends RefCounted

var domain_name: String
var _chain: Array[EffectDefinition] = []

func add_effect(effect: EffectDefinition):
    _chain.append(effect)
    _chain.sort_custom(func(a, b): return a.priority < b.priority)

func calculate(base_value: Variant) -> Variant:
    var result = base_value
    for effect in _chain:
        if effect.condition.is_valid() and effect.condition.call():
            result = effect.calculator.call(result)
    return result
3. 全局效果注册中心
gdscript
# effect_registry.gd （autoload）
var _domains: Dictionary = {}

func register_effect(effect: EffectDefinition):
    for domain_name in effect.target_domains:
        if not _domains.has(domain_name):
            _domains[domain_name] = Domain.new()
            _domains[domain_name].domain_name = domain_name
        _domains[domain_name].add_effect(effect)

func get_domain(name: String) -> Domain:
    return _domains.get(name)

# 跨领域查询
func get_all_effects_for(domain_name: String) -> Array[EffectDefinition]:
    return _domains.get(domain_name, Domain.new())._chain
道具注册示例
gdscript
# 丰收护符：影响地块产量 + 玩家金币获取
var harvest_amulet = EffectDefinition.new()
harvest_amulet.id = "harvest_amulet"
harvest_amulet.target_domains = ["tile", "player"]
harvest_amulet.priority = 100
harvest_amulet.condition = func(): return true

# 对地块：产量 x1.5
harvest_amulet.calculator = func(v): return v * 1.5
# 但这里有个问题：不同 domain 需要不同的 calculator
# 所以实际上应该这样：

var tile_effect = EffectDefinition.new()
tile_effect.id = "harvest_amulet_tile"
tile_effect.target_domains = ["tile"]
tile_effect.priority = 100
tile_effect.calculator = func(yield): return yield * 1.5

var player_effect = EffectDefinition.new()
player_effect.id = "harvest_amulet_player"
player_effect.target_domains = ["player"]
player_effect.priority = 100
player_effect.calculator = func(gold): return gold * 1.5

effect_registry.register_effect(tile_effect)
effect_registry.register_effect(player_effect)
解决"上百种效果"的关键设计
问题	解决方案
效果太多，手动写 calculator 累	用标签系统组合，见下
效果之间有依赖（A需要B先存在）	requires 字段，计算前检查
效果互斥（不能同时生效）	conflicts_with，注册时检测
同类效果要叠加（多个加成）	calculator 统一用 func(v): return v + delta
同类效果要覆盖（取最高）	calculator 统一用 func(v): return max(v, new_val)
标签组合系统（避免写上百个 calculator）
gdscript
# 不用写 calculator，用标签组合
var fertilizer = EffectDefinition.new()
fertilizer.tags = ["yield_bonus", "additive"]  # 产量加成，可叠加
fertilizer.value = 0.2  # +20%

# Domain 内部自动识别标签并计算：
func calculate(base_value: Variant) -> Variant:
    var result = base_value
    for effect in _chain:
        if effect.tags.has("yield_bonus"):
            if "additive" in effect.tags:
                result += result * effect.value      # 叠加
            elif "multiplicative" in effect.tags:
                result *= (1 + effect.value)         # 乘算
    return result
这样 100 种效果可能只需要 5~6 种标签组合，不用写 100 个 calculator。

领域划分建议
Domain 名称	管辖范围	计算内容
tile	所有地块属性	产量、肥力、生长速度、可种植类型
player	玩家自身	速度、采集量、金币倍率
warehouse	仓库	容量、存储损耗率
shop	商店	价格倍率、可售商品列表
inventory	背包	格子数、重量上限
最终数据流
道具使用
  → 生成 EffectDefinition（1个道具可能生成多个，分属不同 domain）
  → effect_registry.register_effect()  ← 自动分发到对应 Domain
  → 每个 Domain 维护自己的有序链
  → 更新时：base_value → Domain.calculate() → 最终值
