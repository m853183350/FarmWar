# 农场工人单位

本文档详细设计第一个作战单位——**农场工人（FarmWorker）**。包括通用单位属性、专属任务系统、AI 状态机、动画/音效控制器，以及与其他系统的交互协议。

---

## 一、概述

农场工人是玩家的基础劳作单位，不可直接操控，所有行为由**任务列表（TaskData 队列）**驱动。工人从任务队列中按 FIFO 顺序取出任务，自动完成移动和执行动作的全过程。

### 设计原则

- **任务驱动**：玩家通过 UI 发出指令（如框选地块 → "种植小麦"），系统将指令转化为任务并分配给工人，工人自动执行
- **顺序执行**：每个工人维护一个任务队列，严格按先进先出顺序执行
- **隐式移动**：工人执行地块操作时，若不在目标地块相邻位置，自动先导航过去，移动对任务系统透明
- **可扩展**：任务类型通过枚举扩展，新动作只需增加 TaskType 枚举值和对应的执行逻辑

### 典型工作流

```
玩家框选 5 块农田 → 菜单点击"种植小麦"
  → UnitManager 查找空闲工人
  → 生成 1 个 PLANT 任务，该任务的子任务内容为在5个地块中种植小麦
  → 分配任务到工人的任务队列
  → 工人 A 依次执行: 移动到地块1 → 种植 → 移动到地块2 → 种植 → ...
  → 每完成一个任务发出 signal，UI 可据此更新
```

## 四、任务系统（核心）

任务是驱动工人行为的唯一方式。每个任务描述一个待完成的原子操作。

### 4.1 任务数据类型（TaskData）

`TaskData` 是一个独立的数据类（使用 `class_name TaskData extends RefCounted`），不依赖场景树。

```gdscript
class_name TaskData
extends RefCounted

## 任务唯一 ID（自增）
var task_id: int = 0

## 子任务，若不为空，需等待所有子任务完成，该任务才算完成
var child_task_id:Array[TaskData] = []

## 父任务，用于快速找到父任务对象
var parent_task_id:TaskData = null

## 任务类型
var task_type: TaskType = TaskType.MOVE

## 目标地块坐标
var target_tile: Vector2i = Vector2i.ZERO

## 额外参数（如 crop_id、item_id 等）
var params: Dictionary = {}

## 任务状态
var status: TaskStatus = TaskStatus.PENDING

## 执行进度（0.0 ~ 1.0），用于需要多 tick 的操作
var progress: float = 0.0

## 所需总 tick 数
var total_ticks: int = 0

## 当前已消耗 tick 数
var elapsed_ticks: int = 0

## 优先级（0=普通，数字越大越优先，预留）
var priority: int = 0

## 创建时的游戏 tick 序号
var created_tick: int = 0
```

### 4.2 任务类型枚举（TaskType）

```gdscript
enum TaskType {
    MOVE,        # 移动到目标地块（不执行操作）
    PLOW,        # 翻耕地块（DIRT → FARMLAND）
    PLANT,       # 种植作物（需指定 crop_id）
    HARVEST,     # 收获作物
    DIG,         # 挖掘地块（STONE → DIRT）
    GATHER,      # 通用采集（砍树、钓鱼等非种植类操作）
    WAIT,        # 原地等待 N tick（用于时序控制，预留）
}
```

### 4.3 任务状态枚举（TaskStatus）

```gdscript
enum TaskStatus {
    PENDING,      # 等待执行（在队列中排队）
    IN_PROGRESS,  # 执行中（正在移动或工作）
    COMPLETED,    # 已完成
    FAILED,       # 执行失败（地块不可操作、路径不通等）
    CANCELLED,    # 被取消（玩家手动取消或全局清空）
}
```

### 4.4 任务参数（params）约定

不同 TaskType 所需的 params 字段：

| TaskType | params 必需字段 | 说明 |
|----------|----------------|------|
| `MOVE` | — | 仅需 target_tile |
| `PLOW` | — | 仅需 target_tile |
| `PLANT` | `crop_id: StringName` | 要种植的作物品种 ID |
| `HARVEST` | — | 仅需 target_tile，目标地块必须有成熟作物 |
| `DIG` | — | 仅需 target_tile |
| `GATHER` | `gather_action: String, rule_id: String` | 采集动作类型和匹配规则 ID |
| `WAIT` | `duration_ticks: int` | 等待的 tick 数 |

### 4.5 任务队列

每个 `FarmWorker` 实例持有一个任务队列：

```gdscript
## 任务队列（FIFO，index 0 为当前任务）
var _tasks: Array[TaskData] = []

## 队列最大长度
var _max_tasks: int = 100000
```

**队列操作：**

```gdscript
## 向队尾追加任务，若父任务不为null则同步修改父任务的child_task_id。队列满时返回 false。
func add_task(task: TaskData, parent_task:TaskData) -> bool

## 向队尾批量追加任务，parent_tasks必须和tasks相同长度。返回一个数组，显示的是每个任务是否添加成功。
func add_tasks_batch(tasks: Array[TaskData], parent_tasks:Array[TaskData]) -> Array[bool]

## 移除队首任务并返回。队列空时返回 null。
func pop_task() -> TaskData

## 清空所有待执行任务（当前 IN_PROGRESS 的任务，以及其有父子关系的任务会继续执行完）。
func clear_pending_tasks() -> void

## 取消所有任务（包括当前正在执行的）。
func cancel_all_tasks() -> void

## 获取队列拷贝（只读）。
func get_tasks() -> Array[TaskData]

## 获取队列中任务数。
func get_task_count() -> int

## 队列是否已满。
func is_queue_full() -> bool

## 队列是否为空。
func is_queue_empty() -> bool
```

### 4.6 任务生命周期

```
创建（new）
  → 加入队列 [PENDING]
  → 轮到队首 → 开始执行 [IN_PROGRESS]
    → 隐式移动阶段（若未到达目标地块）
    → 工作阶段（播放动画，tick 计数递增）
    → 工作进度 >= 1.0 → [COMPLETED]
      → 发出 task_completed 信号
      → 从队列移除
    → 执行中出错（地块状态变化、路径阻塞等） → [FAILED]
      → 发出 task_failed 信号
      → 从队列移除
  → 被取消 → [CANCELLED]
    → 从队列移除
```

### 4.7 任务执行详细流程（每 tick）

```
TickSystem.tick_elapsed(delta)
  → FarmWorker._on_tick(delta):
    1. if _tasks.is_empty() → _set_state(IDLE); return
    2. current = _tasks[0]
    3. match current.status:
       PENDING:
         → _start_task(current)
         → current.status = IN_PROGRESS
         → 设置 current.total_ticks（查表或取 worker 属性）
       IN_PROGRESS:
         → _continue_task(current, delta)
         → _execute_move_phase(current, delta)   # 隐式移动
         → _execute_work_phase(current, delta)   # 工作进度
       COMPLETED / FAILED / CANCELLED:
         → _finish_task(current)
         → _tasks.pop_front()
         → 进入下一个任务
```

### 4.9 工作阶段逻辑

```
_execute_work_phase(task, delta):
    if not _is_move_phase_complete(task):
        return  # 还在移动
    
    task.elapsed_ticks += 1
    task.progress = clamp(float(task.elapsed_ticks) / float(task.total_ticks), 0.0, 1.0)
    
    if task.progress >= 1.0:
        _execute_task_action(task)   # 执行实际操作（调用 TileActions 等）
        task.status = COMPLETED

_execute_task_action(task):
    match task.task_type:
        PLOW:
            TileActions.plow_tiles([task.target_tile])
        PLANT:
            var crop_id = task.params.get("crop_id", "")
            CropManager.plant_crop(task.target_tile, crop_id)   # 待实现，由于player还未完善，需要编写调试用的代码，如提前设定作物类型为小麦
        HARVEST:
            var tile = world.get_tile(task.target_tile)
            var crop = tile.get_content_of_type(ContentType.CROP)
            if crop:
                crop.harvest()
            else:
                task.status = FAILED
        DIG:
            TileActions.dig_tiles([task.target_tile])
        GATHER:
            _execute_gather_action(task, world)   # 根据 params.gather_action 分发
        MOVE:
            pass  # 纯移动，到达即完成
```

**采集动作分发：** GATHER 任务通过 `params.gather_action` 决定实际操作：
- `"dig"` → 调用 `TileActions.dig_tiles()`（挖掘石块）
- `"chop"`、`"fish"` 等 → 通过 `EventBus.gather_action_triggered` 广播（后续接入具体处理逻辑）

## 五、工人 AI 状态机

### 状态转换图

```
         ┌─────────────────────────────┐
         │                             │
         ▼                             │
      ┌──────┐   有任务    ┌────────┐  │ 完成当前任务，队列非空
      │ IDLE │ ────────→ │ MOVING │──┼──────────────────────┐
      └──────┘            └────────┘  │                      │
         ↑                  │    │    │                      │
         │     到达目标位置  │    │    │                      │
         │                  ▼    │    │                      │
         │              ┌────────┐ │  │                      │
         │              │WORKING │ │  │                      │
         │              └────────┘ │  │                      │
         │                   │     │  │                      │
         │        操作完成/失败    │  │                      │
         │                   ▼     ▼  ▼                      │
         │              ┌────────────────┐                    │
         │              │  检查队列      │────────────────────┘
         │              └────────────────┘
         │                   │
         │          队列为空  │
         └───────────────────┘
```

### 状态行为描述

| 状态 | 行为 |
|------|------|
| `IDLE` | 播放 idle 动画，不做任何操作，每 tick 检查是否有新任务进入队列 |
| `MOVING` | 播放 walk 动画，沿寻路路径逐 tick 移动。每 tick 检测是否到达目标相邻格 |
| `WORKING` | 播放对应工作动画（plow/plant/harvest），每 tick 推进 work 进度。期间不响应新指令但不拒绝新任务入队 |
| `COMBAT` | （预留）播放战斗动画，执行战斗逻辑 |
| `DEAD` | 播放死亡动画，完成后移除节点。死亡时清空所有任务 |

### 中断与优先级

- **当前任务不可抢占**：一旦任务进入 IN_PROGRESS，不会被更高优先级任务打断（设计选择，简化逻辑）
- **新任务追加到队尾**：执行中的任务不受影响
- **玩家可手动取消**：选中工人后按取消键 → `cancel_all_tasks()` → 当前任务标记 FAILED，队列清空

## 六、动画系统

### 6.1 AnimationController（子节点）

`AnimationController` 是挂载在单位节点下的通用动画控制组件。它持有 `AnimationPlayer` 引用，根据单位状态切换动画。

```gdscript
class_name AnimationController
extends Node

@export var animation_player: AnimationPlayer

## 播放指定动画。如果已在播放相同动画则跳过。
func play(anim_name: StringName) -> void

## 播放工作动画（plow/plant/harvest），完成后自动切回 idle
func play_work(anim_name: StringName, duration: float) -> void

## 停止当前动画
func stop() -> void
```

### 6.2 动画名称约定

农场工人使用以下 AnimationPlayer 动画名：

| 动画名 | 说明 | 循环 |
|--------|------|------|
| `idle` | 待机站立（呼吸动画或静止） | 循环 |
| `walk` | 行走（上下左右四方向或仅水平翻转） | 循环 |
| `plow` | 翻耕动作（锄头挥动） | 单次 |
| `plant` | 种植动作（弯腰撒种） | 单次 |
| `harvest` | 收获动作（镰刀收割） | 单次 |
| `death` | 死亡倒地 | 单次 |

### 6.3 方向处理

2D 俯视/侧视视角下，通过 `sprite.flip_h` 处理左右朝向。上下动画使用不同动画轨道或在 Sprite 层面处理。

### 6.4 动画与工作同步

工作动画需与 tick 进度同步：

```
work 开始 → animation_controller.play_work("plow", plow_ticks * tick_interval)
         → AnimationPlayer 播放单次动画，时长 = plow_ticks / 20 秒
work 完成 → 动画也恰好结束，切换回 idle
```

- 作物收获后通过 `EventBus.crop_harvested` 自动进入 Storage

### 8.4 与 TickSystem 的交互

- 工人监听 `TickSystem.tick_elapsed` 驱动所有逻辑
- 移动步进、工作进度、动画帧均在 tick 回调中更新
- 逻辑不依赖 `_process()`（保证帧率无关）但画面需要计算插值，以满足高帧率画面流畅

### 8.5 与 UnitManager 的交互

- UnitManager 负责：生成工人、销毁工人、查询空闲工人、分配任务
- 工人在 `_ready()` 向 UnitManager 注册自身
- 工人在 `_exit_tree()` 向 UnitManager 注销自身
- UnitManager 提供 `find_idle_workers(count: int) -> Array[FarmWorker]` 供任务分配使用

### 8.6 与 EventBus 的信号交互

工人通过 EventBus 发出以下信号：

| 信号 | 参数 | 说明 |
|------|------|------|
| `worker_task_completed` | `worker_id: StringName, task: TaskData` | 一个任务完成 |
| `worker_task_failed` | `worker_id: StringName, task: TaskData, reason: String` | 一个任务失败 |
| `worker_queue_empty` | `worker_id: StringName` | 任务队列清空（全部完成） |
| `worker_state_changed` | `worker_id: StringName, old_state: int, new_state: int` | 状态变化 |

## 九、任务分配机制

### 9.1 分配流程

```
玩家操作（选择地块 → 菜单选择动作）
  → UI 发出 EventBus 信号（如 tiles_selected + command）
  → CommandHandler 将指令转化为 TaskData 列表
  → UnitManager.distribute_tasks(task_list)
    1. 按目标地块数量生成 N 个 TaskData
    2. 查找空闲工人（state == IDLE 且队列未满）
    3. 将任务尽可能平均分配到工人的队列中
    4. 若任务数 > 工人可接收数，剩余任务进入全局待分配池
    5. 每次有工人完成/清空任务时，检查并分配全局池中的待分配任务
    6. 若一个任务有子任务，则这个任务的子任务也会优先分配给同一个工人
```

### 9.2 分配策略（可配置）

| 策略 | 说明 |
|------|------|
| `nearest` | 优先分配给距离目标地块最近的空闲工人 |
| `round_robin` | 轮询分配给所有空闲工人 |
| `fill_one` | 尽量塞满一个工人的队列后再分给下一个 |

默认使用 `nearest` 策略。

### 9.3 通过全局待分配池解耦

```gdscript
# UnitManager 中
var _pending_tasks: Array[TaskData] = []

func distribute_tasks(tasks: Array[TaskData]) -> void:
    var workers: Array[FarmWorker] = _find_idle_workers()
    for task in tasks:
        var assigned := false
        for worker in workers:
            if not worker.is_queue_full():
                worker.add_task(task)
                assigned = true
                break
        if not assigned:
            _pending_tasks.append(task)

func _on_worker_task_completed(worker_id: StringName, _task: TaskData) -> void:
    # 工人完成一个任务，尝试分配待分配池中的任务，且需判断这个任务的类型是否是该工人可以执行的，若该任务工人无法执行，则跳过
    # （待实现）优先分配已有任务的子任务
    if _pending_tasks.is_empty():
        return
    var worker: FarmWorker = _find_worker(worker_id)
    if worker and not worker.is_queue_full():
        var task: TaskData = _pending_tasks.pop_front()
        worker.add_task(task)
```

## 十二、异常处理

### 任务失败场景

| 场景 | 处理方式 |
|------|---------|
| 目标地块不可到达（被包围） | 任务标记 FAILED，跳过执行下一个 |
| 目标地块状态已变化（如已被人种了作物） | PLANT → FAILED |
| 目标地块无成熟作物（执行 HARVEST 时） | HARVEST → FAILED |
| 工人执行中被击杀 | 所有 PENDING 任务回收到全局待分配池，当前 IN_PROGRESS 任务标记 FAILED |
| 路径中阻塞 | 每 tick 检测，若 3 秒内无法到达，标记 FAILED |
| 工人队列满 | 拒绝新任务，任务留在全局待分配池 |

### 地块验证

执行任何地块操作前，必须验证地块当前状态：

```
PLOW:  tile.type == DIRT && tile.farmland == false
PLANT: tile.type == FARMLAND && tile.get_content_of_type(CROP) == null
HARVEST: tile.has_content_of_type(CROP) && crop.is_harvestable()
DIG:   tile.type == STONE
GATHER: tile 存在且可通行（预筛选由 GatherActions 负责）
```

验证在 `_start_task()` 中进行，而非在分配任务时——因为任务可能排队很久，轮到执行时地块状态可能已改变。

## 十五、扩展预留

- **多工人协同**：大任务（如开垦大片区域）自动拆分为子任务并分配给多个工人
- **任务优先级**：紧急任务可插队（如敌人来袭时优先收获即将被毁的作物）
- **工具系统**：不同等级工具的 worker 有不同的 work_speed 和可执行的任务类型
- **任务链**：支持条件任务（"如果 A 地块无作物则种植，否则收获"）
- **工人升级**：通过科技树提升 worker 属性
- **搬运任务**：将收获物从地块运送到仓库（当前设计是收获直接入仓）
