# 3.4 自动选兵与战术小队系统 (Phase 4)

## 概述

自动选兵工具是战斗单位指令系统的核心基础设施。玩家不逐个操控作战单位，而是通过**配置战术小队** → **选择目标地块** → **一键派遣**的流程，由系统自动完成"选兵 → 创建任务 → 分配 → 追踪完成"的全链路自动化。

本系统是 Phase 4 的核心交付物，包含以下子系统：

| 子系统 | 类型 | 职责 |
|--------|------|------|
| **SquadConfig / SquadEntry** | Resource | 战术小队配置数据结构 |
| **SquadManager** | Node (GameRoot) | 小队 CRUD + 持久化 |
| **UnitSelection** | RefCounted (静态) | 自动选兵算法 |
| **CombatTask** | RefCounted | 战斗任务数据结构 |
| **CombatTaskFactory** | RefCounted (静态) | 任务工厂 |
| **CommandSystem** | Node (GameRoot) | 指令编排中枢 |
| **SquadTaskTracker** | Node (GameRoot) | 小队任务完成追踪 |
| **ExecuteTaskBehavior** | BaseBehavior (AI) | 任务执行行为 |

## 一、玩家操作流程

### 1.1 操作 1：配置战术小队

玩家通过小队配置界面（UI 设计见 UI 模块文档）配置数个战术小队。每个小队包含若干兵种条目，每个条目指定兵种类型和数量。

**示例配置：**

```
小队 "突击队" (assault_1):
  - swordsman × 3
  - archer    × 2
  - healer    × 1

小队 "侦察队" (scout_1):
  - scout × 2
```

**内置默认小队（始终存在，排在 UI 最后，不可编辑/删除）：**

| 小队 ID | 显示名 | 逻辑 |
|---------|--------|------|
| `idle_all` | 有空的人都过来 | 选中所有空闲（IDLE 且无任务）的友方战斗单位 |
| `all_units` | 全军总攻击 | 选中所有友方战斗单位（无视状态和任务） |

**打开方式：** 点击基地建筑（暂未设计）或按下快捷键 `H`（快捷键应从统一配置文件读取，可配置）。

### 1.2 操作 2：派遣部队

1. 玩家在光标模式下选中一个地块
2. Popup 菜单中出现"派遣部队"选项
3. 子菜单列出所有已配置的战术小队（含两个内置小队）
4. 玩家点击某个小队
5. 系统自动选取距离目标地块最近的、符合条件的空闲单位
6. 为选中单位创建 CombatTask 并分发
7. 单位 AI 自动执行：移动 → 巡逻 → 索敌 → 战斗 → 收集战利品 → 完成

```
玩家操作（选中地块 → Popup → 选择小队）
  ↓
CommandSystem.issue_squad_command(squad_id, tile_position)
  ↓
SquadManager.get_squad(squad_id)                    # 查找小队配置
  ↓
UnitSelection.select_for_squad(config, position)     # 自动选兵
  ↓
CombatTaskFactory.create_for_squad(config, pos, units)  # 创建任务
  ↓
_distribute_tasks(tasks, units)                      # 分发到单位
  ↓
SquadTaskTracker.register_squad(squad_id, tasks)     # 开始追踪
  ↓
EventBus.command_issued.emit(...)                    # 广播通知
  ↓
单位 AIController → ExecuteTaskBehavior → 移动/巡逻/战斗/收集
```

## 二、战术小队系统

### 2.1 SquadEntry — 兵种条目

`Resource`，描述小队中一种兵种的数量要求。

**文件：** `scripts/game/squad_entry.gd`

| 属性 | 类型 | 说明 |
|------|------|------|
| `unit_type` | `StringName` | 兵种类型 ID（如 `"swordsman"`, `"archer"`） |
| `count` | `int` | 该兵种的需求数量 |

### 2.2 SquadConfig — 小队配置

`Resource`，描述一个完整战术小队。

**文件：** `scripts/game/squad_config.gd`

| 属性 | 类型 | 说明 |
|------|------|------|
| `squad_id` | `StringName` | 小队唯一标识（如 `"assault_1"`） |
| `display_name` | `String` | 显示名称（如 `"突击队"`） |
| `entries` | `Array[SquadEntry]` | 兵种组成列表 |
| `sort_order` | `int` | UI 排序权重（越大越靠前，内置小队为 -1/-2） |
| `is_builtin` | `bool` | 是否为内置默认小队 |

**公开方法：**

| 方法 | 说明 |
|------|------|
| `add_entry(unit_type, count)` | 添加一个兵种条目 |
| `remove_entry(index)` | 移除指定索引的条目 |
| `clear_entries()` | 清空所有条目 |
| `get_total_count() -> int` | 获取小队总人数 |

### 2.3 SquadManager — 小队管理器

`Node`，挂载在 `GameRoot` 下。负责小队配置的 CRUD 和 JSON 持久化。

**文件：** `scripts/game/squad_manager.gd`

**数据存储：** `config/squads/squads.json`，格式：

```json
{
    "squads": [
        {
            "squad_id": "assault_1",
            "display_name": "突击队",
            "entries": [
                {"unit_type": "swordsman", "count": 3},
                {"unit_type": "archer", "count": 2}
            ],
            "sort_order": 10
        }
    ]
}
```

**公开方法：**

| 方法 | 返回 | 说明 |
|------|------|------|
| `get_squads()` | `Array[SquadConfig]` | 获取所有小队（含内置，按 sort_order 降序） |
| `get_custom_squads()` | `Array[SquadConfig]` | 获取玩家自定义小队（不含内置） |
| `get_squad(squad_id)` | `SquadConfig?` | 按 ID 查找，null = 不存在 |
| `get_squad_count()` | `int` | 小队总数（含内置） |
| `add_squad(squad)` | `void` | 添加自定义小队，自动保存 |
| `remove_squad(squad_id)` | `bool` | 删除自定义小队（内置不可删） |
| `update_squad(squad_id, new_config)` | `bool` | 更新自定义小队（内置不可改） |

**设计要点：**
- 内置小队（`idle_all`、`all_units`）在 `_ready()` 中自动创建，`is_builtin = true`
- 内置小队的 `sort_order` 为 -1 和 -2（始终排在最后）
- 自定义小队从 JSON 加载，按 `sort_order` 降序排列
- 每次修改自动保存到 JSON

## 三、自动选兵算法

### 3.1 UnitSelection — 选兵工具

`RefCounted`，纯静态工具类。从 `UnitManager` 已注册的战斗单位中按条件自动选取。

**文件：** `scripts/game/unit_selection.gd`

### 3.2 核心方法

#### select_for_squad — 按小队配置选兵

```gdscript
static func select_for_squad(
    squad_config: Resource,
    from_position: Vector2,
    faction: int = 0
) -> Array[CombatUnitBase]
```

**流程：**
1. 判断是否为内置小队：
   - `"idle_all"` → 调用 `select_units(from_pos, -1, "", faction, true, true)`（所有空闲单位）
   - `"all_units"` → 调用 `select_units(from_pos, -1, "", faction, false, false)`（所有单位）
2. 普通小队：遍历 `entries`，对每个 `SquadEntry`：
   - 从 `UnitManager` 按 `unit_type` 获取符合条件的单位
   - 按距离排序 → 截取所需数量 → 加入结果
   - 已选中的 unit_id 加入排除列表，避免重复选取

#### select_units — 通用选兵

```gdscript
static func select_units(
    from_position: Vector2,
    count: int = -1,               # -1 = 不限数量
    unit_type_filter: StringName = &"",
    faction: int = 0,
    only_idle: bool = true,
    exclude_tasked: bool = true,
    exclude_ids: Array[StringName] = []
) -> Array[CombatUnitBase]
```

### 3.3 选择策略

1. 从 `UnitManager.get_combat_units(faction)` 获取所有活跃战斗单位
2. 按以下条件依次过滤：
   - `exclude_ids` — 排除已选中的 ID（避免重复）
   - `unit_type_filter` — 类型匹配（空 = 不限）
   - `only_idle` — 状态为 IDLE
   - `exclude_tasked` — 无当前任务（`current_task == null`）
3. 按 `from_position` 距离升序排列（使用 `distance_squared_to` 避免 sqrt）
4. 若 `count > 0`，截取前 N 个

### 3.4 使用示例

```gdscript
# 按小队配置选取
var squad: SquadConfig = SquadManager.get_squad("assault_1")
var units: Array = UnitSelection.select_for_squad(squad, target_position)

# 选取距离最近的 5 个空闲剑士
var units: Array = UnitSelection.select_units(
    target_position,   # 基准位置
    5,                 # 选取 5 个
    &"swordsman",      # 限剑士类型
    0                  # 友方阵营
)

# 选取所有空闲友方单位（不限类型、不限数量）
var all_idle: Array = UnitSelection.select_units(Vector2.ZERO)
```

## 四、战斗任务系统

### 4.1 CombatTask — 任务数据结构

`RefCounted`，运行时创建，不需要序列化。与 FarmWorker 的 `TaskData` 不同，使用世界坐标、单任务模式、可被全局指令覆盖。

**文件：** `scripts/units/combat_task.gd`

#### 任务类型

| 枚举值 | 中文名 | 说明 |
|--------|--------|------|
| `EXPLORE` | 探索 | 移动到区域中心 → 巡逻游荡 → 自主索敌 |
| `GUARD` | 守卫 | 移动到守卫点 → 原地警戒 → 自动攻击 |
| `ATTACK` | 攻击 | 移动到目标 → 优先攻击 → 清除敌人 |
| `RALLY` | 集合 | 全局覆盖 — 所有友方移动到集结点 |
| `RETREAT` | 撤退 | 全局覆盖 — 所有友方移动到撤退点 |
| `HOLD` | 待命 | 全局覆盖 — 所有友方原地停止 |

#### 任务状态

| 枚举值 | 说明 |
|--------|------|
| `PENDING` | 等待执行 |
| `IN_PROGRESS` | 执行中 |
| `COMPLETED` | 已完成 |
| `FAILED` | 失败（路径不通等） |
| `OVERRIDDEN` | 被全局指令覆盖 |

#### 核心属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `task_id` | `int` | 自增唯一 ID |
| `task_type` | `CombatTaskType` | 任务类型 |
| `target_position` | `Vector2` | 目标位置（世界坐标） |
| `patrol_radius` | `float` | 巡逻半径（格） |
| `status` | `CombatTaskStatus` | 任务状态 |
| `priority` | `int` | 优先级（100 = 全局覆盖） |
| `assigned_unit_id` | `StringName` | 所属单位 ID |
| `squad_id` | `StringName` | 小队 ID（空 = 非小队任务） |
| `task_center` | `Vector2` | 小队任务中心点 |
| `loot_radius` | `float` | 战利品收集半径（格） |

#### 静态工厂

```gdscript
static func create(
    task_type: CombatTaskType,
    position: Vector2,
    unit_id: StringName,
    params: Dictionary = {}
) -> CombatTask
```

### 4.2 CombatTaskFactory — 任务工厂

`RefCounted`，静态工厂。自动从 `config/command/command_params.json` 读取默认参数。

**文件：** `scripts/units/combat_task_factory.gd`

| 方法 | 说明 |
|------|------|
| `create(task_type, position, unit_id, extra_params)` | 创建单个任务 |
| `create_for_squad(squad_config, position, units)` | 为小队创建批量任务（共享 squad_id + task_center） |
| `create_global_override(task_type, position, unit_id)` | 创建全局覆盖任务（priority = 100） |

### 4.3 与 TaskData 的差异

| 维度 | FarmWorker TaskData | CombatTask |
|------|-------------------|------------|
| 基类 | RefCounted | RefCounted |
| 坐标 | `target_tile: Vector2i`（网格） | `target_position: Vector2`（世界） |
| 队列 | FIFO 多任务队列 | 单任务（一个时刻一个） |
| 覆盖 | 不可抢占 | 全局指令可 OVERRIDDEN |
| 分配 | `UnitManager.distribute_tasks()` | `CommandSystem → UnitSelection` |
| 小队 | 无 | 有 `squad_id`，SquadTaskTracker 追踪 |
| AI 关系 | 任务驱动全部行为 | 任务是 AI 的输入，无任务时自主运行 |

## 五、指令系统

### 5.1 CommandSystem — 指令编排中枢

`Node`，挂载在 `GameRoot` 下。负责：接收玩家指令 → 选兵 → 创建任务 → 分发 → 追踪。

**文件：** `scripts/game/command_system.gd`

#### 三种指令模式

**1. 小队指令（主要玩家入口）**

```gdscript
func issue_squad_command(squad_id: StringName, position: Vector2) -> int
```

对应"派遣部队"流程。返回选中的单位数量（0 = 无可用单位）。

**2. 通用指令**

```gdscript
func issue_command(
    command_type: int,     # EXPLORE / GUARD / ATTACK
    position: Vector2,
    unit_count: int = -1,
    unit_type_filter: StringName = &""
) -> int
```

适用于不需要小队配置的场景（如调试、脚本批量操作）。

**3. 全局覆盖指令**

```gdscript
func issue_global_override(
    command_type: int,     # RALLY / RETREAT / HOLD
    position: Vector2 = Vector2.ZERO
) -> void
```

不通过选兵机制，直接通过 EventBus 信号广播给所有友方单位：
- `RALLY` → `EventBus.command_override_rally.emit(position)`
- `RETREAT` → `EventBus.command_override_retreat.emit(position)`
- `HOLD` → `EventBus.command_override_hold.emit()`

所有友方单位的 `AIController` 收到信号后：
1. 标记当前任务为 `OVERRIDDEN`
2. 创建全局覆盖任务（`priority = 100`）
3. 切换到 `ExecuteTaskBehavior`

#### 信号

| 信号 | 说明 |
|------|------|
| `command_issued(command_type, params)` | 指令发出（本地通知，供 UI 反馈） |
| `squad_command_issued(squad_id, position, count)` | 小队指令发出 |

### 5.2 全局覆盖指令的详细行为

| 指令 | 单位行为 | 途中遇敌 | 任务完成后 |
|------|---------|---------|-----------|
| RALLY | 全部移动到集结点 | 自卫还击 | 进入 Guard（原地警戒） |
| RETREAT | 全部移动到撤退点 | 仅限近距离自卫 | 进入 Guard |
| HOLD | 原地停止，减速到零 | 被攻击时还击 | 保持 HOLD 直到新指令 |

## 六、小队任务追踪

### 6.1 SquadTaskTracker — 完成条件检查

`Node`，挂载在 `GameRoot` 下。连接到 TickSystem，每 10 tick 轮询一次活跃小队的完成状态。

**文件：** `scripts/game/squad_task_tracker.gd`

#### 小队任务完成条件（全部满足才判定完成）

1. **未被外部中断** — 所有成员的任务状态均非 `OVERRIDDEN`
2. **所有成员仇恨为空** — 无威胁目标（敌人全部清除）
3. **范围内战利品已清空** — `task_center + loot_radius` 范围内无 `group("loot_item")` 节点
4. **所有成员已到达** — 每个成员距离 `task_center` 不超过 `patrol_radius × 64 + 32` 像素

#### 完成流程

```
SquadTaskTracker._on_tick() → 每 10 tick 轮询
  → 遍历 active_squads
  → _check_squad_complete(data):
      全部条件满足
        → active_squads.erase(squad_id)
        → EventBus.squad_task_completed.emit(squad_id)
        ↓
  → ExecuteTaskBehavior 收到信号（匹配 squad_id）
    → unit.current_task.mark_completed()
    → EventBus.combat_task_completed.emit(unit_id, task_id)
    → 切换到 Loot（如果挂载）→ Guard
```

### 6.2 ExecuteTaskBehavior — 任务执行行为

AI 行为模块之一。当 `unit.current_task != null` 时，由 `AIController` 切换到本行为。

**文件：** `scripts/units/ai/behaviors/execute_task_behavior.gd`

#### 两种任务模式

**普通任务（无 squad_id）：**
```
移动到 target_position
  → 到达（dist < ARRIVAL_THRESHOLD）
  → mark_completed()
  → EventBus.combat_task_completed
  → 切换到 Guard
```

**小队任务（有 squad_id）：**
```
移动到 target_position
  → 到达 → 进入巡逻模式
  → 在 task_center ± patrol_radius 范围内巡逻
  → 主动索敌（HatredSystem 扫描 PATROL_ALERT_RANGE 范围）
  → 发现敌人 → Chase → Combat → 战斗结束 → 回到巡逻
  → 收到 EventBus.squad_task_completed 信号
  → mark_completed()
  → 收集战利品（Loot） → Guard
```

#### 途中的自卫逻辑

| 任务类型 | 途中遇敌行为 |
|---------|------------|
| 普通任务 | 仅限 `SELF_DEFENSE_RANGE`（5 格）内自卫，不主动追击 |
| 小队任务 | 主动索敌（`PATROL_ALERT_RANGE` = 10 格），追击并战斗 |
| RETREAT | 仅限 `SELF_DEFENSE_RANGE` 内自卫 |
| HOLD | 被攻击时自卫，不移动 |

## 七、完整数据流

### 7.1 派遣部队完整流程

```
┌─────────────────────────────────────────────────────────────┐
│ 玩家操作层                                                    │
│ 选中地块 → Popup → "派遣部队" → 选择小队                       │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────────┐
│ CommandSystem.issue_squad_command("assault_1", tile_pos)     │
│                                                              │
│  1. SquadManager.get_squad("assault_1")                      │
│     → SquadConfig { entries: [swordsman×3, archer×2] }       │
│                                                              │
│  2. UnitSelection.select_for_squad(config, tile_pos, 0)      │
│     → 从 UnitManager 获取所有 faction=0 的战斗单位             │
│     → 遍历 entries:                                          │
│         "swordsman" → 按距离排序 → 取前 3 个空闲的 swordsman   │
│         "archer"    → 按距离排序 → 取前 2 个空闲的 archer      │
│     → 返回 [swordsman_1, swordsman_2, swordsman_3,           │
│              archer_1, archer_2]                              │
│                                                              │
│  3. CombatTaskFactory.create_for_squad(config, pos, units)   │
│     → 为每个 unit 创建 CombatTask:                            │
│         task_type = ATTACK                                    │
│         squad_id = "assault_1"                                │
│         task_center = tile_pos                                │
│         loot_radius = 10.0 (从 command_params.json)          │
│         patrol_radius = 5.0                                   │
│                                                              │
│  4. _distribute_tasks(tasks, units)                          │
│     → 遍历: unit_i.current_task = task_i                     │
│     → task_i.mark_in_progress()                               │
│     → EventBus.combat_task_assigned.emit(unit_id, task_id)   │
│                                                              │
│  5. SquadTaskTracker.register_squad("assault_1", tasks)      │
│     → 开始每 10 tick 轮询完成条件                             │
│                                                              │
│  6. EventBus.command_issued.emit(...)                         │
│     → UI 层收到通知，显示 "已派遣 5 个单位"                    │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌─────────────────────────────────────────────────────────────┐
│ 单位 AI 层                                                    │
│                                                              │
│ AIController.update(unit):                                   │
│   unit.current_task != null → _update_task_mode()            │
│   → BehaviorFSM.switch_to("ExecuteTask")                     │
│                                                              │
│ ExecuteTaskBehavior:                                          │
│   阶段 1: 移动 → 向 target_position 移动                      │
│         途中遇敌 → 切 Chase/Combat（自卫 → 返回任务）         │
│   阶段 2: 到达 → 巡逻模式（仅小队任务）                       │
│         在 task_center ± patrol_radius 范围巡逻               │
│         主动索敌 → Chase → Combat → 回到巡逻                  │
│   阶段 3: 收到 squad_task_completed 信号                      │
│         → mark_completed() → Loot → Guard                    │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 全局覆盖指令流程

```
CommandSystem.issue_global_override(RALLY, position)
  ↓
EventBus.command_override_rally.emit(position)
  ↓
所有友方单位 AIController._on_rally_command(position):
  1. 旧任务 mark_overridden()
  2. EventBus.combat_task_overridden.emit(unit_id, task_id)
  3. current_task = CombatTaskFactory.create_global_override(RALLY, pos, unit_id)
  4. BehaviorFSM.switch_to("ExecuteTask")
  ↓
ExecuteTaskBehavior:
  RETREAT → 向撤退点移动，途中只自卫
  RALLY   → 向集结点移动，途中自卫
  HOLD    → 原地减速到零，被攻击时自卫
  → 到达后无事可做 → 等新指令 / 玩家手动取消
```

### 8.1 小队配置

```json
{
    "squads": [
        {
            "squad_id": "assault_1",
            "display_name": "突击队",
            "entries": [
                {"unit_type": "swordsman", "count": 3},
                {"unit_type": "archer", "count": 2}
            ],
            "sort_order": 10
        }
    ]

```

初始为空数组。SquadManager 首次运行时自动创建内置小队。

### 8.2 指令默认参数

**路径：** `config/command/command_params.json`

```json
{
    "default_unit_count": -1,
    "patrol_radius": 5.0,
    "loot_radius": 10.0,
    "explore_radius": 12.0,
    "arrival_threshold": 8.0,
    "path_update_interval": 20,
    "scan_interval_ticks": 10,
    "max_distance_for_selection": 100.0
}
```

| 参数 | 说明 |
|------|------|
| `default_unit_count` | 默认选兵数（-1 = 不限） |
| `patrol_radius` | 小队巡逻半径（格） |
| `loot_radius` | 战利品收集半径（格） |
| `explore_radius` | 探索任务半径（格） |
| `arrival_threshold` | 到达目标判定阈值（像素） |
| `path_update_interval` | 路径更新间隔（tick） |
| `scan_interval_ticks` | SquadTaskTracker 扫描间隔（tick） |
| `max_distance_for_selection` | 选兵最大距离（格，预留） |
