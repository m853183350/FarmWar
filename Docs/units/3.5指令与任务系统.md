# 3.5 指令与任务系统 (Phase 4)

## 概述

Phase 4 实现战斗单位的指令与任务系统。玩家不逐单位操控，而是发高层指令 → 系统自动选兵 → 创建 CombatTask → 分派 → 单位 AI 自主执行。

## 架构

```
玩家操作（框选区域 / 地块 Popup 选择小队）
  → CommandSystem 接收指令
    → SquadManager 查找小队配置
    → UnitSelection 自动选兵
    → CombatTaskFactory 创建 CombatTask
    → 分发到各单位
    → SquadTaskTracker 追踪小队完成状态
  → 单位 AIController 检测 current_task → 进入任务模式
  → ExecuteTaskBehavior 执行任务（移动 → 战斗 → 巡逻 → 收集战利品）
  → 任务完成 → 回到自主模式
```

## 核心组件

### CombatTask — 战斗任务数据结构

`RefCounted`，运行时创建不需序列化。使用世界坐标而非网格坐标。单任务模式（一单位同一时刻只持有一个），可被全局指令覆盖。

- `task_type`: EXPLORE / GUARD / ATTACK / RALLY / RETREAT / HOLD
- `target_position`: 目标位置（世界坐标）
- `squad_id`: 小队 ID（空 = 非小队任务）
- `task_center`, `loot_radius`, `patrol_radius`: 小队任务参数

### SquadConfig — 战术小队配置

`Resource`，描述一个小队的兵种组成。两个内置默认小队（`is_builtin = true`）始终排在 UI 最后：

| 小队 ID | 显示名 | 逻辑 |
|---------|--------|------|
| `idle_all` | 有空的人都过来 | 选所有空闲友方战斗单位 |
| `all_units` | 全军总攻击 | 选所有友方战斗单位（无视状态） |

### SquadManager — 小队管理器

`Node`，挂 GameRoot。提供小队的 CRUD，序列化到 `config/squads/squads.json`。内置小队不可删除/修改。

### UnitSelection — 自动选兵工具

`RefCounted`，纯静态方法。核心方法：
- `select_for_squad(squad_config, position, faction)` — 按小队配置选兵
- `select_units(position, count, type_filter, faction, only_idle, exclude_tasked)` — 通用选兵

选择策略：从 UnitManager 获取所有战斗单位 → 按条件过滤 → 按距离排序 → 截取所需数量。

### CommandSystem — 指令系统

`Node`，挂 GameRoot。玩家指令的统一入口：
- `issue_squad_command(squad_id, position)` — 小队指令（"派遣部队"）
- `issue_command(type, position, count, filter)` — 通用指令
- `issue_global_override(type, position)` — 全局覆盖（RALLY/RETREAT/HOLD）

全局覆盖通过 EventBus 信号广播，所有友方 AIController 收到后覆盖当前任务。

### CombatTaskFactory — 任务工厂

`RefCounted`，静态工厂。自动从 `config/command/command_params.json` 读取默认参数。

### SquadTaskTracker — 小队任务追踪

`Node`，挂 GameRoot。每 10 tick 轮询活跃小队，检查完成条件：
1. 所有成员任务未被覆盖
2. 所有成员仇恨为空
3. 范围内战利品已清空
4. 所有成员到达目标区域

全部满足 → `EventBus.squad_task_completed.emit(squad_id)`。

### ExecuteTaskBehavior — 任务执行行为

AI 行为之一，当 `unit.current_task != null` 时由 AIController 切换到此行为。

两种模式：
- **普通任务**：到达目标 → 标记完成 → 切 Guard
- **小队任务**：到达目标 → 巡逻 task_center → 主动索敌 → 战斗 → 收集战利品 → 等待 SquadTaskTracker 确认完成 → 切 Loot → Guard

## 双模式架构（AIController）

```
AIController 每 tick 决策:

  if unit.current_task != null:
    任务优先模式
      → ExecuteTaskBehavior 执行任务目标
      → 普通任务：到达即完成
      → 小队任务：巡逻 + 主动索敌 + 收集战利品
      → 途中遇敌 → 自卫/主动战斗
      → 战斗结束 → 继续执行任务
  else:
    自主模式
      → Guard/Patrol → 发现敌人 → Chase → Combat → Loot → Guard
      → 低血量 → Flee
```

## 全局覆盖指令

| 指令 | 信号 | 行为 |
|------|------|------|
| RALLY | `command_override_rally(position)` | 所有友方移动到集结点 |
| RETREAT | `command_override_retreat(position)` | 所有友方移动到撤退点，只自卫 |
| HOLD | `command_override_hold()` | 所有友方原地待命，不主动索敌 |

通过 EventBus 信号广播，不依赖 UnitSelection/UnitManager 遍历。AIController._ready() 中连接信号。

## 与 FarmWorker 任务系统的对比

| 维度 | FarmWorker TaskData | CombatTask |
|------|-------------------|------------|
| 基类 | RefCounted | RefCounted |
| 坐标 | target_tile: Vector2i (网格) | target_position: Vector2 (世界) |
| 队列 | 多任务 FIFO 队列 | 单任务（一个时刻一个） |
| 覆盖 | 不可抢占 | 全局指令可 OVERRIDDEN |
| 分配 | UnitManager.distribute_tasks() | CommandSystem → UnitSelection |
| AI 关系 | 任务驱动全部行为 | 任务是 AI 的输入，无任务时自主运行 |
| 小队 | 无 | 有 squad_id，SquadTaskTracker 追踪完成 |
