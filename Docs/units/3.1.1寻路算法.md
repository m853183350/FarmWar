## 寻路算法

可自主行动的单位的寻路算法都放在 `UnitBase` 基类中，根据需求调用。当前框架已预留寻路接口（`_move_path`、`_try_find_path()` 等），`pathfinding.gd`（独立寻路模块，`scripts/units/pathfinding.gd`）实现后接入。

### 标准寻路算法（HPA\* 分层寻路）

#### 为什么选 HPA\*

地图规模预计在几百×几百地块（数万节点），若每 tick 多个单位同时执行全量 A\*，性能压力很大。**HPA\*（Hierarchical Pathfinding A\*）** 将地图划分为固定大小的簇（cluster），在簇级别构建抽象图，在线查询时仅在抽象图上跑 A\*，再将结果细化为逐格路径。抽象图节点数远小于完整网格，典型加速比 10~50 倍。

#### 概述

整体分两大阶段：

| 阶段 | 时机 | 内容 |
|------|------|------|
| **预处理**（离线） | 地图生成后 / 地形变更时 | 划分簇 → 识别入口 → 构建抽象图（入口间的最短路径） |
| **在线查询** | 每次寻路请求 | 在抽象图上 A\* → 细化抽象路径为逐格路径 |

#### 坐标系统

| 概念 | 逻辑坐标 | 世界空间坐标 |
|------|---------|-------------|
| 地块中心 | `(grid_x + 0.5, grid_y + 0.5)` | `(grid_x * 64 + 32, grid_y * 64 + 32)` |
| 单位锚点 | `grid_position`（底部中点） | `global_position` |

- `TILE_SIZE = 64` 像素
- `grid_position` 取整后除以 `TILE_SIZE` 得到对应的地块 `Vector2i`：`Vector2i(roundi(grid_position.x / 64), roundi(grid_position.y / 64))`
- 路径的起点/终点均为**地块中心的世界坐标**，保证单位停在格子正中央

#### 成本网格构建

寻路前从 `world` 节点（`TerrainGenerator`）读取所有地块数据，构建一个 `map_width × map_height` 的二维成本数组。成本网格是底层 A\* 和抽象图构建的共同基础。

```
成本网格构建流程：
1. 遍历 world 的所有子节点（地块实例）
2. 对每个地块读取其 TileInfo（通过 get_meta("tile_data") 或 BaseTile.get_tile_data()）
3. 查表获取该地块类型的移动成本
4. 填入 cost_grid[grid_x][grid_y]
```

成本查表优先级：
1. **特定细项配置**（如 `"soil_farmland": 2`）—— 按 `variant` 精确匹配，优先级最高
2. **地块大类配置**（如 `"farmland": 2`）—— 按 `tile_type` 分类匹配
3. **默认值** —— 未配置的类型默认成本为 2

#### 移动成本配置（JSON）

配置文件路径：`config/pathfinding_cost.json`

```json
{
  "tile_type_costs": {
    "dirt": 2,
    "stone": 2,
    "farmland": 2,
    "ocean": -1,
    "slope": 3,
    "rough": 5,
    "special": 50
  },
  "variant_costs": {
    "wetland": 2,
    "soil_farmland": 2,
    "shallow": 4,
    "deep": -1,
    "river": -1,
    "stone_road": 1.7,
    "pebble": 2,
    "hard_stone": 3
  }
}
```

**成本语义：**
| 成本值 | 含义 |
|--------|------|
| `0.1 ~ 1.9` | 优质路面（低成本前进，在上面行动会有加成） |
| `2 ~ 5` | 常见地形 |
| `50+` | 极端地形（如熔岩），几乎不会走但理论上可通过 |
| `-1` | **不可通行**（水域、悬崖等），算法不会将其加入搜索 |

**设计原则：**
- 数字越小成本越低，算法倾向于选择总成本最小的路径
- 负数表示不可通过，搜索时跳过该节点
- `variant_costs` 优先级高于 `tile_type_costs`，允许对特定变种覆写（如 `"shallow"` 浅水区成本为 4 而非默认 `ocean` 的 -1）
- 未出现在配置中的类型/变种默认成本为 2

#### 簇划分（Cluster Partition）

将完整地图网格切分为固定大小的方形簇。簇大小需在**抽象粒度**与**抽象图精度**之间平衡：

| 簇大小 | 抽象图节点数 | 优势 | 劣势 |
|--------|------------|------|------|
| 8×8 | 较多 | 路径更接近最优 | 预处理和查询较慢 |
| 10×10 | 适中 | **推荐默认值**，平衡精度与性能 | — |
| 16×16 | 较少 | 查询极快 | 路径质量下降，绕路增多 |

```gdscript
# 簇大小可通过 JSON 配置
const CLUSTER_SIZE: int = 16  # 默认 16×16

# 地图边缘的簇可能不满 CLUSTER_SIZE × CLUSTER_SIZE
# 簇在网格中的坐标：(cluster_x, cluster_y)，其中
#   cluster_x = tile_x / CLUSTER_SIZE  (整数除法)
#   cluster_y = tile_y / CLUSTER_SIZE
```

#### 入口识别（Entrance）

**入口（entrance）** 是两个水平或垂直相邻簇之间，双方均可通行的**相邻地块对**。入口是抽象图的节点。

```
识别算法（每对相邻簇 C1 和 C2）：
1. 找到 C1 与 C2 的共享边界（一条长度为 CLUSTER_SIZE 的线段）
2. 遍历边界上的每个地块对 (t1, t2)，其中 t1∈C1, t2∈C2
3. 若 t1 和 t2 均可通行（cost ≥ 0），则将这对地块标记为一个 entrance
4. 为避免冗余：若连续多个格子都是 entrance，只保留每个连续段的两端和中间一个过渡点（压缩 entrance 数量）
```

**特殊情况：**
- 若两个簇之间完全被不可通行地块隔开（如水域），则该边界上没有 entrance——实际表现为两个簇在抽象图中无直连边，路径需绕行其他簇
- 地图边界处没有 entrance（不连接簇外）

#### 抽象图构建（Abstract Graph）

抽象图以**入口**为节点，以入口之间在**同一簇内**的最短路径为边。

```
构建流程（预处理阶段，首次寻路前或地形变更后执行）：
1. 遍历所有簇
2. 对每个簇 C：
   a. 收集 C 的所有 entrance（来自四条边界）
   b. 对 C 内的每一对 entrance (e1, e2)：
      - 在 C 内部运行底层 A*（仅搜索 C 范围内的格子，最多 CLUSTER_SIZE² 节点）
      - 若 e1 到 e2 可到达，将这条路径的距离成本记录为抽象边 (e1 → e2, cost)
      - 缓存完整的簇内路径（避免在线查询阶段再跑簇内 A*）
3. 抽象图存储为 Dictionary[Vector2i, Array[Edge]]，其中 Edge = {to: Vector2i, cost: float, path: Array[Vector2i]}
   - key 为 entrance 标识（取入口处任一地块坐标）
```

#### 底层 A\*

预处理阶段的簇内 entrance 间寻路、在线查询阶段的临时节点连接，以及同簇短路场景，均使用同一套底层 8 方向 A\*。底层 A\* 仅在小范围（最多 `CLUSTER_SIZE²` 格，默认 100 格）内搜索。

- **节点**：网格中的每个地块 `(x, y)`，只要成本 ≥ 0（可通过）
- **邻接**：8 方向（上下左右 + 四角），允许斜向移动
- **移动成本**：水平/垂直 = `cost_grid[to_x][to_y]`，斜向 = `cost_grid[to_x][to_y] * √2`
- **启发式**：八方向对角线距离（可接受，保证最优）

```
h(n) = D * (dx + dy) + (D2 - 2 * D) * min(dx, dy)
```

其中 `D = 1`、`D2 = √2`、`dx = abs(n.x - goal.x)`、`dy = abs(n.y - goal.y)`

由于底层 A\* 搜索范围很小（≤100 格），开放集使用 `Array[Dictionary]` + 线性查找最小 f 值节点即可，无需优先队列。

##### 底层 A\* 伪代码

```gdscript
# 底层 A*（限定搜索范围 bounds）
func _low_level_astar(start: Vector2i, goal: Vector2i, bounds: Rect2i) -> Array[Vector2i]:
    var open_set: Array[Dictionary] = []
    var came_from: Dictionary = {}
    var g_score: Dictionary = {}
    
    g_score[start] = 0.0
    open_set.append({"tile": start, "f": _heuristic(start, goal), "g": 0.0})
    
    while not open_set.is_empty():
        var current: Dictionary = _pop_min_f(open_set)
        var cur_tile: Vector2i = current["tile"]
        
        if cur_tile == goal:
            return _reconstruct_path(came_from, cur_tile, start)
        
        for neighbor in _get_8_neighbors(cur_tile, bounds):
            if cost_grid[neighbor.x][neighbor.y] < 0: continue
            if _is_diagonal(cur_tile, neighbor) and not _can_cut_corner(cur_tile, neighbor): continue
            
            var move_cost: float = cost_grid[neighbor.x][neighbor.y]
            if _is_diagonal(cur_tile, neighbor):
                move_cost *= 1.41421356  # sqrt(2)
            
            var tentative_g: float = g_score[cur_tile] + move_cost
            if not g_score.has(neighbor) or tentative_g < g_score[neighbor]:
                g_score[neighbor] = tentative_g
                came_from[neighbor] = cur_tile
                var f: float = tentative_g + _heuristic(neighbor, goal)
                _update_or_add(open_set, neighbor, f, tentative_g)
    
    return []  # 不可达
```

##### 斜向移动的墙角约束

当斜向移动经过的两个相邻格子均不可通行时，阻止该斜向移动，防止单位"穿墙"：

```gdscript
func _can_cut_corner(from: Vector2i, to: Vector2i) -> bool:
    var dx := to.x - from.x
    var dy := to.y - from.y
    var side1 := Vector2i(from.x + dx, from.y)
    var side2 := Vector2i(from.x, from.y + dy)
    return cost_grid[side1.x][side1.y] >= 0 and cost_grid[side2.x][side2.y] >= 0
```

#### 在线查询

每次单位请求寻路时，执行以下步骤：

```
HPA* 在线查询流程：
find_path(start_tile, goal_tile):

  1. 同簇短路：起点和终点在同一个簇内？
     → 若是，直接在该簇内跑一次底层 A*，返回结果
     → （短距离移动最常见的场景，无需走抽象图）

  2. 临时插入起点和终点到抽象图：
     a. 包含 start 的簇 Cs：
        - 在 Cs 内跑底层 A*，找到 start 到 Cs 每个 entrance 的最短路径
        - 将 start 作为临时节点加入抽象图，边为 (start → entrance_i, cost_i)
     b. 包含 goal 的簇 Cg：
        - 在 Cg 内跑底层 A*，找到每个 entrance 到 goal 的最短路径
        - 将 goal 作为临时节点加入抽象图，边为 (entrance_i → goal, cost_i)

  3. 在抽象图上运行 A*（节点数 = entrance 总数 + 2）：
     - 节点：所有 entrance + start 临时节点 + goal 临时节点
     - 边：预计算的簇内抽象边 + 临时插入的 start/goal 边
     - 启发式：两节点所属簇中心的八方向对角线距离

  4. 细化抽象路径为逐格路径：
     - 抽象路径：[start → E1 → E2 → ... → Ek → goal]
     - 展开：
       a. start → E1: 使用步骤 2a 缓存的簇内路径
       b. 每个 Ei → E(i+1): 使用预处理时缓存的抽象边路径
       c. Ek → goal: 使用步骤 2b 缓存的簇内路径
     - 拼接所有子路径，转为世界坐标

  5. 返回逐格世界坐标路径点列表
```

##### 抽象图 A\* 的细节

抽象图节点数通常在几百到几千量级（如 256×256 地图用 10×10 簇 → 约 26×26 个簇 → 约 1350 个 entrance），远比完整网格（65536 节点）小。开放集用 `Array[Dictionary]` 线性查找即可。

- **节点**：entrance 标识 `Vector2i`
- **邻接**：查找该 entrance 所属簇在抽象图中的所有出边（预处理时已计算）
- **启发式**：簇中心坐标的八方向对角线距离

##### 在线查询伪代码

```gdscript
func find_path(start_tile: Vector2i, goal_tile: Vector2i) -> Array[Vector2]:
    # 1. 确保成本网格和抽象图是最新的
    _ensure_cost_grid()
    _ensure_abstract_graph()
    
    # 2. 起点/终点不可通过 → 返回空
    if cost_grid[start_tile.x][start_tile.y] < 0: return []
    if cost_grid[goal_tile.x][goal_tile.y] < 0: return []
    
    # 3. 同簇短路
    var cs := _get_cluster(start_tile)
    var cg := _get_cluster(goal_tile)
    if cs == cg:
        var tile_path: Array[Vector2i] = _low_level_astar(start_tile, goal_tile, _cluster_bounds(cs))
        return _tiles_to_world(tile_path)
    
    # 4. 临时插入 start/goal 到抽象图
    var temp_edges: Dictionary = {}  # 临时边，不影响缓存的抽象图
    _insert_temp_node(start_tile, cs, temp_edges, true)   # start → entrances
    _insert_temp_node(goal_tile, cg, temp_edges, false)    # entrances → goal
    
    # 5. 抽象图 A*
    var abstract_path: Array[Vector2i] = _abstract_astar(start_tile, goal_tile, temp_edges)
    if abstract_path.is_empty():
        return []
    
    # 6. 细化为逐格世界坐标路径
    return _refine_path(abstract_path, temp_edges)
```

#### 抽象图缓存与失效

| 缓存项 | 存储内容 | 失效条件 |
|--------|---------|---------|
| 成本网格 | `cost_grid[width][height]` | 地形变更事件（`EventBus.terrain_changed`） |
| 簇级抽象图 | 所有 entrance + 簇内边（含路径） | 成本网格失效时整体重建 |
| 单簇抽象边 | 该簇内所有 entrance 对的最短路径 | 该簇范围内有地块成本变更时局部重建 |

**局部失效优化**：地块变更通常只影响少量簇（如建筑放置影响几个格子）。此时：
1. 标记受影响的簇为"脏"
2. 下次寻路时，仅重算脏簇的抽象边
3. 其他簇的缓存边继续使用

地形变更信号 `EventBus.terrain_changed` 携带变更的地块坐标列表，`pathfinding.gd` 据此标记脏簇。

#### 路径跟随

寻路完成后返回 `Array[Vector2]`（世界坐标路径点列表），存入 `UnitBase._move_path`。每 tick 沿路径点依次移动：

```
路径跟随流程（UnitBase._execute_move_phase 内）：
1. 若 _move_path 为空 → 调用 _try_find_path() 寻路
2. 取出 _move_path[_path_index] 作为当前子目标
3. 向子目标直线移动（每 tick 前进 move_speed * TILE_SIZE * tick_interval 像素）
4. 到达子目标（距离 < 1px）→ _path_index += 1
5. _path_index 达到数组末尾 → 到达最终目标，发出 move_completed 信号
```

HPA\* 返回的路径点在 entrance 附近可能有折线。通过**路径平滑**（见下）合并共线点后可减少转折。

#### 动态避障与重新寻路

移动过程中若路径被新障碍物阻挡：

```
每 tick 在移动前检测：
1. 当前子目标所在的地块是否变为不可通过（建筑放置、地块转换等）
   → 清空 _move_path，设置 _waiting_for_path = true
2. 等待 FIND_PATH_WAIT_TIME（0.5 秒）后重新寻路
   → 此时该地块可能已恢复通行，或找到新路径
   → 重新寻路时标记的脏簇会被重建，保证抽象图反映最新地形
3. _find_path_fail_count += 1
4. 连续失败 FIND_PATH_FAIL_MAX（10 次）→ 判定为卡死，执行瞬移（是否可瞬移需在对象中配置）
```

**障碍来源：**
- 地块类型转换
- 建筑放置占用地块
- 其他单位临时占据地块

#### 路径平滑

HPA\* 输出的路径会在 entrance 附近产生折线。**String Pulling（拉绳法）** 在后处理中将共线路径点合并：

```
对路径点 P[0..n]：
1. 设 left = 0, right = 1
2. 若 line_of_sight(P[left], P[right+1]) 无阻挡
   → right += 1（拉直，跳过中间点）
3. 否则
   → 保留 P[right]，left = right，right += 1
4. 重复直到 right = n
```

`line_of_sight` 通过 Bresenham 直线遍历检查路径经过的所有地块是否可通过。

#### 性能估测

| 地图规模 | 簇数 (10×10) | entrance 数（估） | 抽象图 A\* 节点 | 底层 A\*（每次） |
|---------|-------------|------------------|----------------|-----------------|
| 64×64 | 7×7 | ~98 | ~100 | ≤100 格 |
| 128×128 | 13×13 | ~338 | ~340 | ≤100 格 |
| 256×256 | 26×26 | ~1352 | ~1354 | ≤100 格 |
| 512×512 | 52×52 | ~5408 | ~5410 | ≤100 格 |

**每次寻路的开销 = 抽象图 A\*（~数百到数千节点）+ 2 次簇内底层 A\*（≤100 格）+ 路径拼接**。即使在 512×512 地图上，仍可维持在毫秒级，远比全量 A\* 搜索数万节点高效。

**多单位场景**：多个单位同时发起寻路时，抽象图是共享的（只读），无需每人重建。簇内底层 A\* 不可共享（每个单位起终点不同），但每次 ≤100 格搜索非常快。

#### 与 UnitBase 现有框架的集成

`UnitBase` 已预留以下变量和方法，`pathfinding.gd` 实现后直接接入：

| UnitBase 成员 | 类型 | 用途 |
|-------------|------|------|
| `_move_path: Array[Vector2]` | 私有变量 | 存储路径点（世界坐标） |
| `_path_index: int` | 私有变量 | 当前跟踪的路径点索引 |
| `_waiting_for_path: bool` | 私有变量 | 是否正在等待重新寻路 |
| `_path_wait_timer: float` | 私有变量 | 寻路等待计时器 |
| `_find_path_fail_count: int` | 私有变量 | 连续寻路失败计数 |
| `_try_find_path()` | 私有方法 | 调用寻路模块，填入 `_move_path` |
| `_teleport_to_target()` | 私有方法 | 瞬移到目标（卡死兜底） |
| `FIND_PATH_WAIT_TIME` | 常量 | 0.5 秒 |
| `FIND_PATH_FAIL_MAX` | 常量 | 10 次 |

**接入方式：**

```gdscript
# UnitBase._try_find_path() 接入 pathfinding.gd
func _try_find_path() -> void:
    var start_tile: Vector2i = get_current_tile()
    var target_tile: Vector2i = Vector2i(
        roundi(_target_position.x / TILE_SIZE),
        roundi(_target_position.y / TILE_SIZE)
    )
    
    _move_path = Pathfinding.find_path(start_tile, target_tile)
    
    if _move_path.is_empty():
        _find_path_fail_count += 1
        if _find_path_fail_count >= FIND_PATH_FAIL_MAX:
            _teleport_to_target()
        else:
            _waiting_for_path = true
            _path_wait_timer = 0.0
    else:
        _find_path_fail_count = 0
        _path_index = 0
        _waiting_for_path = false
```
